# Эстафета: Claude Code и Codex по очереди на одном репозитории

*Записка тимлида, 2026-09-05 (переписана под реальную схему: агенты работают **не параллельно**, а по
очереди — кто-то один, пока не кончатся токены). Готовые файлы для репозитория — `analysis/agents/`.*

---

## 0. Что изменилось и почему это проще

Изначально я расписывал параллельную работу (владение файлами, волны, worktree). Реальная ситуация другая:
Claude сделал часть работы и остался без токенов, вы отдали продолжение Codex, у него тоже кончились
токены. Значит, задача не «чтобы не мешали друг другу», а **«чтобы каждый мог подхватить с того места,
где предыдущий оборвался — без объяснений в чате»**.

Это эстафета. Правила эстафеты короче правил параллельной работы:

1. **Единственная память — `origin`.** Контекст чата умирает вместе с сессией. Всё, что не запушено или не
   записано в `docs/process/HANDOFF.md`, не существует для следующего агента.
2. **Сначала HANDOFF, потом код.** Агент пишет в HANDOFF §5 «сейчас делаю X», *а потом* делает X.
   Если его оборвут — следующий найдёт план, а не загадку.
3. **Push после каждого зелёного шага**, шаги ≤ 45 минут. Разрешены `wip:`-коммиты в рабочей ветке; в
   `main` попадают только squash-мерджи, `wip` там исчезают.

## 2. Файлы (готовы в `analysis/agents/`, кладутся в репо один раз)

| В репо | Что это |
|---|---|
| `AGENTS.md` | Правила эстафеты — читают оба (Codex читает по стандарту, Claude — по ссылке из CLAUDE.md) |
| `CLAUDE.md` | Дополнение для Claude: трейлер, где включать ultracode, skills |
| `docs/process/HANDOFF.md` | **Эстафетная палочка.** 11 секций: кто держит, текущая задача, сделано (с хэшами), недоделано, **следующий шаг дословно**, статус гейтов числами, блокеры, изменения контрактов, ловушки, очередь, журнал сессий |
| `scripts/handoff_check.py` | Запускается первым в каждой сессии: ветка, HEAD, незапушенные/незакоммиченные файлы, число Alembic-head'ов, что утверждает HANDOFF; печатает предупреждения («HEAD — wip», «палочка у X, но 15 часов без коммитов → сессия оборвана») |
| `.github/PULL_REQUEST_TEMPLATE.md` | PR только с реальным выводом гейтов; чек-лист ревьюера |
| `KICKOFF_PROMPTS.md` (не в репо, для вас) | 4 промпта: A — обычный старт, B — первый запуск (установка файлов), C — восстановление после обрыва, D — ревью работы другого |

Установка (любой агент, у которого есть токены, по промпту B; или вы руками):
```bash
cp analysis/agents/AGENTS.md analysis/agents/CLAUDE.md .
mkdir -p docs/process scripts
cp analysis/agents/HANDOFF.md docs/process/
cp analysis/agents/handoff_check.py scripts/
cp analysis/agents/PULL_REQUEST_TEMPLATE.md .github/
git add -A && git commit -m "docs: relay workflow for the two ai engineers, with a handoff file and a check script" && git push
```
Папку `analysis/` тоже закоммитьте в репо (бриф, спека, референс должны быть внутри рабочей копии агентов,
а не только у вас на диске).

## 3. Как проходит одна сессия

```
 старт ──► git fetch; python scripts/handoff_check.py  (вывод — в чат)
       ──► прочитать AGENTS.md + HANDOFF.md целиком
       ──► сверить дерево с HANDOFF §1–§5: незакоммиченное? wip-HEAD? гейты красные? шаг уже сделан?
       ──► если §2 = ready-for-review от другого агента → сначала ревью (промпт D)
       ──► взять палочку: HANDOFF §1, §11 → commit "handoff: <я> takes the baton at [0.3]" → push
       ──► отчёт вам ≤ 10 строк: где остановились, точный следующий шаг, какие файлы
 работа ─► цикл: HANDOFF §5 = «делаю X» → делаю X → гейты → commit (+trailer) → push → §3 += хэш
       ──► ловушки → §9; изменения контрактов → §8; красные тесты → wip: + §6
 финал ─► (если успел) §1 Holder: nobody, §5 следующий шаг дословно, §6 числа, §11 строка →
           commit "handoff: <я> releases the baton …" → push → вам: «HEAD abc123, next: …»
```

Ключевая мысль: **финал необязателен**. Сессия, оборванная посреди «работы», уже является чистой передачей,
потому что HANDOFF §5 написан заранее, а последний пуш был ≤ 45 минут назад.

## 4. Ваша роль (≈ 15 минут на переключение)

1. Кончились токены у A → открываете B, вставляете промпт **A** из `KICKOFF_PROMPTS.md` (или **C**, если
   знаете, что A оборвался посреди правки файлов).
2. Читаете 10-строчный отчёт B. Если он говорит «HANDOFF и код расходятся» — отвечаете на вопрос; если
   нет — «продолжай».
3. Раз в день: `handoff_check.py` у себя + просмотр HANDOFF §7 (вопросы вам) и §6 (числа гейтов).
4. PR со статусом `ready-for-review`: попросите *другого* агента сделать ревью (промпт D), затем
   squash-merge сами. Эстафета — это и есть кросс-ревью: каждый читает работу другого при приёме палочки.

Что не делать: не пересказывать агенту в чате «Claude вчера делал то-то» — если это не в HANDOFF/git,
это неправда с вероятностью 50 %. Заставьте его читать файл.

## 5. Ветки и коммиты

- Одна ветка на задачу брифа: `task/0.1-profile-priorities`, от `main`. **Оба агента коммитят в неё по
  очереди.** В `main` — только squash-merge через PR, никогда `--force` в общую ветку.
- Сообщения — стиль репо: `feat: rank with a geometric mean so an unaffordable place cannot buy its way to the top`;
  плюс `wip: [0.3] u_* ported, aggregate() still fails T3` для обрывов и
  `handoff: codex takes the baton at [0.3]` для смены рук.
- Порядок задач — очередь в HANDOFF §10 = порядок брифа. Следующую задачу не начинать, пока предыдущая
  не в `main` (исключение — если §5 явно велит ветвиться от ветки предшественника).
- Миграции Alembic: до и после — ровно один head (`handoff_check.py` это считает). Миграцию, уже попавшую
  в `main`, не переписывать.

## 6. Ловушки эстафеты и предохранители

| Что ломается | Предохранитель |
|---|---|
| Агент «помнит» из чата то, чего нет в git | Промпт заставляет читать HANDOFF; §3 принимает только пункты с хэшами |
| Оборвался с незакоммиченными файлами | `handoff_check.py` покажет их; промпт C: `git diff` каждого → вердикт в §4 → `wip:`-коммит или именованный stash |
| Второй агент переделывает уже сделанное | §3 с хэшами + §5 дословный; kickoff требует сверки до кода |
| Второй агент «улучшает» формулу или решение | D1–D12 в hard rules; T1 в CI; сверка с `reference/ranking_v2.py` в чек-листе PR |
| Два Alembic-head'а | Проверка в скрипте; правило «один head до и после» |
| Codex-sandbox не может пушить в origin | AGENTS.md §7: агент говорит об этом сразу; вы пушите через UI после каждого шага, HANDOFF ведётся внутри диффа |
| Красные тесты «забыли» упомянуть | Красные при пуше → обязательно `wip:` + список в §6 |
| Кто автор — непонятно | Трейлер `Agent:` в каждом коммите; скрипт печатает его в логе |
| Долгий обрыв (сутки) при `Holder: claude` | Скрипт: палочка у X, но > 2 ч без коммитов → «считай сессию оборванной, забирай палочку и запиши это» |

## 7. Реалистичные ожидания

Эстафета не ускоряет работу — она убирает потери на переключение (по опыту это 30–60 минут «а что тут
было?» на каждую смену плюс риск переделки). Скорость — как у одного агента, но без простоев, когда у него
кончились токены. Если позже появится возможность держать обоих одновременно — вернёмся к параллельной
схеме (владение файлами по слоям, worktree); её набросок остался в истории этого файла, но сейчас он не
нужен.
