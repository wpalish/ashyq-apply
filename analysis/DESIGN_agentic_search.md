# Дизайн: агентный поиск университетов с детерминированным «позвоночником»

*Ответ на предложение: «не строить базу, а построить workflow ИИ-модели, которая ищет в интернете:
рейтинги с весами авторитетности → первый список → анализ eligibility → форумы (Reddit) для
инсайдов о приёмных комиссиях».*

---

## 1. Вердикт по идее

| Элемент предложения | Оценка | Что делаем |
|---|---|---|
| Не строить огромную БД заранее | **Согласен.** Поддержка каталога на 3 000 вузов — это отдельный продукт | Каталог **вырастает сам** из исследований агента (lazy-built, см. §4) |
| ИИ ходит по рейтингам с весами авторитетности | **Согласен**, простая и полезная штука | Таблица весов в §5, консенсус-ранг через взвешенную медиану |
| ИИ проводит анализ eligibility «по заданному алгоритму» | **Частично.** Eligibility уже есть, детерминированный и хороший. ИИ его *не заменяет* | ИИ **находит страницы и извлекает claim'ы**; сравнение с профилем остаётся кодом |
| ИИ шарится по Reddit за инсайдами о приёмках и red flags | **Идея ценная, реализация через Reddit — рискованная** (§6) | Отдельный слой «Community insights»: помечен, датирован, никогда не влияет на score |

**Главный тезис:** ИИ — это **исследователь и извлекатель**, но не **судья**. Всё, что определяет
результат (eligibility, score, портфель), остаётся детерминированным кодом, который можно
протестировать. ИИ закрывает ровно ту дыру, где проект сейчас слабее всего: **найти правильные
страницы** (live-recall — 1 вуз из 10) и **найти кандидатов вообще** (10 вузов в реестре).

Кстати, автор проекта это предвидел: в схеме `Claim` уже есть `extraction_method = "llm_assisted"`,
а папка `.claude/skills/` — это фактически готовые системные промпты для агента
(`university-admissions-research`, `scholarship-audit`).

## 2. Четыре правила, которые нельзя нарушить

Проект живёт на доверии («каждая цифра — со ссылкой»). Агент встраивается так, чтобы это не сломать.

1. **Профиль не уходит наружу без явного согласия.** Сейчас `ASSUMPTIONS.md` прямо запрещает поисковые
   запросы, потому что они несут контекст абитуриента третьей стороне. Агентные запросы строятся
   **только из предпочтений** (уровень, направление, страны, язык обучения) — это не персональные
   данные. GPA, IELTS, гражданство, бюджет **никогда не попадают в промпт**: сравнение идёт локально.
2. **Claim без цитаты не существует.** Агент предлагает `(claim_type, value, url, excerpt)`. Код
   скачивает страницу и **проверяет, что excerpt реально есть в тексте** (нормализованное вхождение).
   Нет совпадения → claim отбрасывается, а не «доверяется». Это защита от галлюцинаций.
3. **Агент не ранжирует и не оценивает.** Ни одно число из ответа LLM не попадает в score. LLM
   возвращает URL'ы, классификацию страниц и извлечённые факты. Всё.
4. **Источник и дата у всего.** Community-инсайты — тоже с URL и датой, но в отдельном ярусе
   источников («анекдот — только контекст»), ниже ответа приёмной комиссии.

## 3. Целевая архитектура

```
 профиль (локально)
   │
   ▼
 1. VALIDATE ──────────────────────────────── код (как есть)
   │
   ▼  запрос БЕЗ персональных данных: {level, field→ISCED, countries, language}
 2. DISCOVER ───────► ResearchAgent.discover()          ┐
   │                    • рейтинги (QS/THE/ARWU/subject) │  LLM + web search
   │                    • веса авторитетности            │  результат: список
   │                    • кандидаты с домена и URL       │  (name, country, city,
   │                    ◄── shared cache (university)    ┘   homepage, rank evidence)
   │
   ▼  hard-фильтры + pre-score по атрибутам ──────────── код (новый retrieval-слой)
 3. VERIFY ────────► ResearchAgent.locate_pages(univ, programme, level)   ← главная ценность ИИ
   │                    → {program_url, admissions_url, costs_url, scholarships_url}
   │                 ResearchAgent.extract_claims(page_html, claim_types)
   │                    → [(type, value, excerpt)]
   │                 ExcerptValidator ─── код: excerpt ∈ page_text ? accept : drop
   │                 существующие rule-based extractors остаются как второй источник
   │
   ▼
 4. FUNDING ───────► то же самое для страниц стипендий; классификация — код (funding.py)
   │
   ▼
 5. ASSESS ────────────────────────────────── код: eligibility.py (как есть)
   │                                             scoring: геометрика + coverage (новое)
   │                                             portfolio: safety/match/reach (новое)
   │
   ▼
 5b. INSIGHTS ─────► ResearchAgent.community_insights(univ, programme)   ← отдельная панель
                       → [{quote, url, date, source_type}] с дисклеймером
                       никогда не входит в score
```

### Интерфейс `ResearchAgent` (adapters/research/agent.py)

```python
class ResearchAgent(Protocol):
    async def discover(self, q: DiscoveryQuery) -> list[CandidateLead]        # §5
    async def locate_pages(self, lead: CandidateLead, programme: str, level: str) -> PageSet
    async def extract_claims(self, page: FetchedPage, wanted: list[ClaimType]) -> list[ProposedClaim]
    async def community_insights(self, lead: CandidateLead, programme: str) -> list[Insight]
```

Реализации: `LlmResearchAgent` (прод), `FixtureResearchAgent` (demo/тесты — тот же корпус, что
сейчас). Провайдер LLM и поисковый API — за интерфейсом, меняются конфигом.

### Что остаётся детерминированным и почему

| Компонент | Остаётся кодом | Причина |
|---|---|---|
| `eligibility.py` | да | Правила асимметрий (unknown ≠ barrier) — это юридически-этическая логика, её нельзя доверять стохастике |
| scoring / coverage / portfolio | да | Должно быть воспроизводимо и тестируемо; один и тот же профиль → один и тот же порядок |
| `funding.py` классификация | да | «Full ride» по таблице покрытия — правила |
| conflicts / freshness / currency | да | Как есть |
| Fetcher (robots, rate-limit, PII-guard) | да | Агент ходит в сеть **только через него** |

## 4. Shared research cache = «ленивый каталог»

Исследование «TU Delft, BSc Computer Science, набор 2027» **одинаково для всех абитуриентов**.
Кэшируем на уровне `(university, programme, level, intake)`, а не на уровне пользователя:

- TTL привязываем к существующим окнам свежести в `freshness.py` (дедлайны — короче, требования — дольше).
- Через N запусков кэш становится тем самым каталогом, который мы не строили руками — но каждая
  запись в нём родилась из реального исследования с источниками.
- Persist в существующий PostgreSQL (таблица `research_cache`), никакой новой инфраструктуры.
- Экономика: без кэша прогон на 20 вузов ≈ 100–200 страниц через LLM. Грубая оценка стоимости —
  единицы долларов за прогон; с кэшем 10-й пользователь с тем же направлением/странами стоит центы.
  (Цифры ориентировочные; посчитаем точно на пилоте.)

## 5. Рейтинги с весами авторитетности

Рейтинги остаются **discovery-only** (правило проекта: они не могут подтвердить требование или цену).
Но для программного standing и для отбора кандидатов — полезны. Предлагаемая таблица (параметры,
не константы):

| Источник | Вес | Комментарий |
|---|---|---|
| QS World University Rankings | 1.0 | глобальный, ежегодный |
| Times Higher Education (THE) | 1.0 | глобальный |
| ARWU (Shanghai) | 0.8 | сильный research-bias, слабо отражает bachelor |
| U.S. News Best Global | 0.8 | |
| **QS / THE by Subject** (совпало с направлением) | **1.3** | предметный рейтинг важнее общего для абитуриента |
| CSRankings, Nature Index и т.п. (нишевые) | 1.0 при совпадении поля | только если поле совпадает |
| Национальные рейтинги (CHE, Guardian, Maclean's) | 0.6 | несравнимы между странами |
| Агрегаторы/блоги «Top 10 universities for…» | **0** | не источник |

Консенсус-ранг = взвешенная медиана `log(rank)` по найденным источникам. Логарифм — потому что
разница #5 vs #20 значима, а #500 vs #520 нет. Каждый ранг хранится как claim с URL и годом
(схема `RankingEntry` уже есть).

## 6. Community insights: Reddit — честная оценка

### Что даёт
Информации типа «на этот факультет смотрят на олимпиады, а не на волонтёрство», «эссе про
семейный бизнес — red flag, слишком шаблонно», «стипендию X в реальности дают 2–3 иностранцам в год» —
нет ни на одной официальной странице. Это реальная ценность для абитуриента из Казахстана.

### Почему не «просто парсить Reddit»

- **Условия использования.** Reddit Data API запрещает коммерческое использование без отдельного
  письменного разрешения; с июня 2026 (Responsible Builder Policy) каждый разработчик проходит
  approval; коммерческий тир — порядка $12k/мес; неавторизованный скрапинг блокируется.
- **Направление движения.** 5 августа 2026 Reddit объявил постепенное ограничение публичного Data API
  и перевод сторонних приложений на свою Developer Platform (Devvit). Строить на этом фундаменте —
  значит закладывать миграцию через год.
- **Эпистемика.** Форумный пост — анекдот от анонима с неизвестной датой и мотивацией. Продукт,
  который обещает «каждая цифра со ссылкой», не может подмешивать это в eligibility или score.

### Как сделать правильно

1. **Отдельный ярус, отдельная панель.** В source hierarchy проекта добавляется уровень 8:
   *community anecdote — context only*. В UI — четвёртая вкладка рядом с Eligibility / Admissions
   fit / Funding fit: **«Что говорят студенты»** с дисклеймером, каждая цитата — ссылка + дата +
   тип источника.
2. **Источники шире Reddit и юридически чище:**
   - **собственный social-модуль ASHYQ Apply** (уже реализован: feed, threads, Discover) — долгосрочно
     главный источник, и он *наш*;
   - официальные блоги студентов-амбассадоров и student unions вузов (это официальные домены);
   - публичные форумы с доступным доступом: The Student Room (UK), College Confidential, GradCafe;
   - Reddit — **через поисковый инструмент LLM-провайдера** с атрибуцией ссылки (у крупных
     провайдеров есть лицензии на Reddit-контент), а не через собственный клиент Data API. Если
     позже появится бюджет и одобрение — подключим API официально.
3. **Формат вывода жёстко ограничен.** Агент возвращает `{claim_text, url, posted_at, source_type,
   topic ∈ {extracurriculars, essays, scholarships, interviews, culture}}`. Формулировка всегда
   «студенты сообщают, что…», никогда «приёмная комиссия требует…». Тест на это — как тест на
   отсутствие PII в audit log.
4. **Red flags по активностям** — как *вопросы к абитуриенту*, а не вердикты: «Несколько студентов
   пишут, что для этого факультета ценят проекты с кодом на GitHub выше сертификатов курсов. У вас в
   профиле 3 сертификата и 0 проектов — стоит ли это изменить?» Это ложится на существующий механизм
   `UnresolvedQuestion`.

## 7. Оценка качества агента (без этого не выкатываем)

В репозитории уже есть canary — 10 реальных вузов и аудит claim-by-claim (`docs/CANARY_AUDIT.md`,
`docs/LIVE_DISCOVERY_REPORT.md`). Он становится eval-набором для агента:

| Метрика | Сейчас (sitemap-эвристики) | Гейт для агента |
|---|---|---|
| Programme-page recall | 1 / 10 | ≥ 7 / 10 |
| Category-page recall (admissions/costs/scholarships) | 26 / 30 | ≥ 27 / 30 |
| Material false positives (claim, не подтверждённый страницей) | 0 | **0** (excerpt-валидатор) |
| Детерминизм финального порядка при одном кэше | — | 100 % |
| Утечка персональных данных в исходящие запросы | тест есть | тест расширяется на промпты |

Плюс воспроизводимость: все ответы агента логируются с промптом и версией модели, чтобы регрессию
можно было отбить фикстурой.

## 8. Риски и как их закрываем

| Риск | Митигация |
|---|---|
| Галлюцинации агента | Excerpt-валидатор (правило 2); LLM никогда не «последний источник» |
| Стоимость и латентность | Shared cache; агент только там, где rule-based не справился (escalation, как сейчас Playwright-tier) |
| Недетерминизм от прогона к прогону | Кэш фиксирует найденное; ранжирование — чистая функция от кэша |
| Смена ToS у форумов | Community-слой изолирован и опционален; продукт работает без него |
| Vendor lock на LLM | Интерфейс `ResearchAgent`, prompt'ы — из `.claude/skills/` в репозитории |
| Приватность | Профиль не в промптах (по умолчанию); отдельный явный toggle, если захотим profile-aware поиск |
