# Offline local transport feasibility audit

Date: 2026-10-06. Parent-declared frozen source: `e327498`; original V13 trial `CLOSED_UNSCORED` after runner allocation failure. This note is prospective. No stock entrypoint, model CLI, provider, university, GH, report, seal or label operation was run. No environment, credential, reviewed/signed label, HELDOUT or original trial data was read. The Exa credential is pending owner input; its absence/identity was not independently inspected here.

## Conclusion

Local execution is technically feasible using the existing Exa adapter, strict controller and strict live child entrypoint. It is **not launch-ready**: the frozen stock calls do not themselves establish secret-free selector environments, an isolated configuration/import root, or pacing continuity between short-lived processes. A small parent transport and a distinct local receipt/report branch are needed; Fetcher, parsing, source validation and budget core need no relaxation.

Owner design preference at this checkpoint: a **persistent per-case wrapper using the unchanged Fetcher/execute APIs**, with tested opt-in shared STOP admission for every source tool. The fresh-CLI/global-serialization approach below remains an alternative only. Neither design is launch-ready without its own frozen parent/runtime/receipt gates. This note implements neither.

Fresh controller processes each construct a new Fetcher. Consequently they re-check current robots, but do not share its in-memory robots cache, unreachable/stalled-host memory or per-host last-request time. Do not describe fresh-process CLI execution as an identical persistent Fetcher session.

For a narrow CLI-only design, the parent can preserve conservative spacing without core edits: serialize Fetcher processes and admit the next only after the previous process has fully terminated plus **10 seconds**, the stock maximum accepted Crawl-delay. Apply this globally to Fetcher processes unless a separately proven host-aware scheduler covers all redirect hosts. Model time already spent after the preceding completion satisfies the barrier; no extra ten seconds is added when the barrier has elapsed. Every internal request happened before the preceding completion, so this conservative barrier covers ordinary 1.5-second pacing and every accepted Crawl-delay up to ten seconds. Fetcher still refuses larger Crawl-delay values and independently revalidates robots for each new process. The wait consumes the original immutable 900-second case guard, is recorded separately, and never grants a fresh period or invents raw source elapsed time/counters.

This preserves conservative inter-process spacing plus fresh robots enforcement. It does **not** preserve robots cache or stalled-host latch continuity. If exact session-state parity is required, fresh stock CLI calls alone cannot provide it: a persistent per-case wrapper must retain the unchanged Fetcher/provider objects and call the existing `execute` API, or state must be explicitly transferred by an audited wrapper. That is a larger transport change and should not be silently substituted. No new persistent-worker protocol is implemented or required by this note.

## Minimum parent-only changes

1. **Explicit environment boundary.** Construct the orchestration/selector allowlist before starting the parent. Inject the owner-supplied key only into the controlled source child environment or a worker-only input channel. `select` can remain unchanged if its parent environment is demonstrably clean. Close secret-bearing descriptors before selector spawn; rely on `close_fds=True` and no unintended inheritable handles. Do not dump environment values or Settings.
2. **Controlled immutable source/CWD.** Bind the executable source tree and canonical CWD; exclude `.env`, user configuration, credentials and unrelated artifacts. Source workers need no access to other experts or score labels. Baseline's existing reviewed identity registry is a separate trusted input consumed by stock capture (`live.py:299`); use its already approved frozen hash without exposing it to selectors or treating it as score labels. No new registry or label read was performed for this audit.
3. **Fresh paths and subprocess control.** Absolute executable and argument list, `shell=False`, exact canonical source CWD, exclusive claimed stage/action directory, single-link regular output files, no replacement/symlink aliases, process-group timeout/reap. A direct `live --child` call uses stock capture but requires a truthful parent `Capture` envelope; copying/relabeling a prior capture is not acceptable.
4. **Preserved Fetcher state, shared STOP and fixed guard.** The owner-preferred persistent per-case worker retains the unchanged Fetcher/provider state. Its opt-in shared STOP admission must cover both search and fetch tools, publish the original first-cause marker durably before peers observe STOP, and admit no following tool after provider/model/integrity failure. That wrapper still needs new tests and runtime proof. If the fresh-CLI alternative is selected instead, use the conservative process barrier above; record completed process, planned barrier, actual admission and wait duration, with no overlapping Fetcher children under that simple scheme. In either design, check the original absolute deadline immediately before any tool/spawn; waiting/resume never resets it.
5. **Local receipt identity.** Use `transport_kind="local_process_v1"` and a fresh local UUID. Do not fabricate GH run ID, headSha, runner conclusion or successful remote provenance. Add a local provenance branch to the parent/report and retain the common raw/counter/citation/budget/isolation/prefix validators. Missing, unknown or contradictory source counters remain preseal ineligible.

These are transport/configuration changes. No parsing/core/Fetcher/robot/PII/DNS weakening, provider/model/account substitution, 30/55/10-second selector cap, low-effort override or extra source allowance is proposed.

- [ ] Owner supplies the same authorized Exa credential through a private local channel after the transport is frozen. Do not inspect a repository `.env` or copy a GH secret through logs/artifacts. No purchase, account rotation, key workaround or quota retry.
- [ ] Orchestration and every selector have an explicit non-secret environment allowlist. Keep only needed normal locale/temp/PATH and the legitimate existing desktop login context. Do not repurpose HOME/CODEX_HOME or switch account identity. Exclude all provider/API/auth override values and unrelated `UNIMATCH_*` flags; pin existing default-effort Astra CLI argv.
- [ ] Source environment alone includes `UNIMATCH_EXA_API_KEY`; all other allowed source settings are public pinned values. Never propagate it back to orchestration, selectors, baseline/expert prompts or result serialization.
- [ ] Remove uppercase/lowercase proxy variables, custom CA overrides and Python/dynamic-loader injection variables (`PYTHONPATH`, `PYTHONHOME`, user-site hooks, `LD_*`, `DYLD_*`). Use a controlled interpreter/import root. Stock clients trust environment; omission from an audit receipt is not removal from the actual process environment.

Keep optional capture experiments/documents off unless already explicitly predeclared in the frozen comparison; do not inherit ambient flags.

- [ ] Disable HTTP header/body debug logging and prevent exception/environment dumps. Worker failure metadata remains fixed diagnostic/status. Originals needed for evidence stay access-protected and immutable; do not silently redact/rewrite original raw source bytes to make validation pass.
- [ ] Seal all original accepted and rejected/in-flight streams before any label operation. Existing selector sealed-root/sentinel proof covers current source/trial/private/history/sibling roots; current selector workspace remains usable. No label path, bindings, diagnosis or other expert answer enters a selector prompt.
