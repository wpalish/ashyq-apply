# Безопасность и конфиденциальность ASHYQ Apply — 9 октября 2026

Срез: 2026-10-09T03:17:22.552341+00:00. Проверенный исполняемый commit: `5b48d5e43d0ba7247c850ba4556584ab7415a986`.
Инженерный раунд: **квалифицированное локальное принятие кода, полного прогона и ограниченного браузерного сценария**. Юридический пакет — **DRAFT**,
готовность опубликованного продукта ещё не подтверждена.

## Что изменилось в продукте

| Изменение | Проверяемая граница |
|---|---|
| Модераторские права назначаются по ID аккаунта | Самостоятельная регистрация с email из прежнего allowlist не выдаёт права модератора. Сам список доверенных ID задаёт оператор |
| Приватные ответы API получили `Cache-Control: no-store` | Обычные ответы и проверенные ветви отказа; это не проверка всех upstream/неперехваченных 500 или опубликованного CDN |
| Черновики и отметки разделены по пользователю и workspace | Серверная идентичность устанавливается до восстановления приватного экрана. Workspace остаётся общей границей организации |
| Смена аккаунта блокирует устаревшую вкладку и поздние ответы | Кооперативный протокол браузера; не атомарная смена общей cookie, защита от XSS или шифрование localStorage |
| Выход и удаление показывают успех только после подтверждения сервера | Отказ сохраняет текущие данные; сохранённый кейс доступен для экспорта/удаления и без исследования |
| Повторный вход восстанавливает разрешённый сервером кейс | После очистки браузерных указателей читается список доступных кейсов; новые локальные намерения и поздние ответы учитываются |
| Удаление очищает уже открытый JSON и блокирует его позднее возвращение | Только прямые профильные Show/Download данного экрана. Ранее скачанные файлы и отдельная выгрузка shortlist не отзываются |
| Публичная правовая страница описывает реальные границы | Не обещает полного стирания, гарантированного поступления, анонимного поиска или действующего согласия без серверной записи |

Ровно **20 уникальных путей кода/тестов** в этом раунде: 5 backend и 15 frontend.
Это не 20 отдельных уязвимостей. Для финального исправления Export независимый
native peer выполнил 39 случаев: 15 новых + 22 прежних + 2 собственных сценария
с настоящим StoreProvider. Два собственных сценария на старом компоненте дали
assertion RED. Повторные suites и одинаковые тесты двух БД не складываются.

## Документы

Пакет [docs/legal/README](../legal/README.md) содержит политику конфиденциальности,
условия использования, спецификацию согласий и полномочий, реестр получателей и
передач, хранение и обращения, порядок реагирования на инциденты, readiness и
поля фактов оператора. [SECURITY.md](../../SECURITY.md) описывает технические
границы. Версия `2026-10-09.draft1` сохраняется как проект.

Политика различает кейс, аккаунт, общий workspace, публичное сообщество,
переписку, документы, оплату, журналирование и внешних получателей. Удаление
из активной БД не объявляется стиранием jobs/audit/payment/backups/копий у
получателей. Регистрация пока не записывает принятую версию политики или
полномочия представителя; страница политики не заменяет эту реализацию.

## Что остаётся до запуска

1. Подтвердить юридического оператора и действующий контакт по данным, страны
   основной БД, резервных копий и журналов, получателей и их договорные условия.
   Регион `ams` приложения этого не доказывает.
2. Утвердить реальные цели, сроки хранения и процедуру несовершеннолетних;
   реализовать серверную запись согласий/полномочий и проверить её.
3. Закрыть следующие подтверждённые технические вопросы: сохранение отвергнутых
   PII-значений в диагностике, атомарное использование reset token и проверка
   наследования security headers Nginx. Их проектирование не считается исправлением.
4. Проверить эксплуатацию конкретной опубликованной версии: права, заголовки,
   резервирование/восстановление, обращения, инциденты и полный путь вошедшего
   пользователя. Docker/containers и hosted required checks не выдаются за PASS.
5. Получить принятое свежее качество поиска. Существующий Exa STOP сохраняется;
   этот раунд не возобновлял live или экспертный controller и не менял провайдера.

Опубликованные положения Unilight, UCAS, Common App и College Board использованы
как ориентиры в [сравнении](evidence/product-loop/2026-10-09/security-round/competitor-privacy/REPORT.md).
Это сравнение политики и пользовательских обещаний, не аудит их серверов.
Превосходство по безопасности или удобству без независимого измерения не заявляется.

Следующий цикл: конкретная подтверждённая потеря/утечка → небольшой общий патч →
независимые отрицательные и положительные проверки → локальные gates → передача
в [HANDOFF](HANDOFF.md). История и оригинальные отказы сохраняются.
