# Results screens in Russian and Kazakh (gap B6), 2026-10-19

Gap B6 in `KB_E2E_SMOKE_2026-10-19.md`: the locale switcher offers ru and kk, but the results screens
and every backend-generated question were hard-coded English. This note is the inventory and what
was done about each string.

## How it works

- **Frontend labels.** `frontend/src/lib/i18n.results.ts` holds 404 keys: 321 for the interface and
  83 `msg.*` keys for backend sentences. `EN_RESULTS` is spread into the existing `EN` dictionary in
  `i18n.ts`, so `t()` and the locale switcher work as before. `RU_RESULTS` and `KK_RESULTS` are full
  `Record`s, not `Partial`s, so an English key without both translations does not compile. New
  helpers: `tf` (parameters), `tn` (one/other count), `tOr(key, english)` for English owned
  elsewhere, and `rich()` for sentences that contain elements.
- **English owned by `format.ts`.** Status chips (`STATUS_LABEL`, `STATUS_MEANING`), the stale age
  chip and the fit disclaimer go through `tOr`. An English reader still gets `format.ts`'s own text,
  so the parallel B8 wording work (for example "Ageing" becoming "Not current") is not undone by a
  copy in the catalogue. Only ru and kk read the catalogue.
- **Backend sentences.** Stored payloads are unchanged; the golden demo hash still passes. On the way
  out, `app/domain/message_keys.py` recognises each English sentence against a template and attaches
  a `MessageRef {key, params, parts}` beside it. The new API fields are additive and absent when
  unset (`exclude_if`):
  - `UnresolvedQuestion.question_message`, `.why_message`
  - `FundingGap.reason_message`, `.warning_messages` (index for index with `warnings`)
  - `ClaimOut.stale_messages` (one per "; "-separated reason in "Stale, not current: …")

  `annotate_result` runs only on served objects: `GET /results` and `/results/{id}`, decision and
  notes responses (after the payload is written), `/shortlist`, and `/questions`.
  `frontend/src/lib/messages.ts` `localize(ref, english)` renders `msg.<key>` with the parameters.
  It falls back to the served English when there is no key, no translation, a missing parameter or
  an English reader. A reworded generator that nobody re-keyed is therefore shown in correct
  English, never as a stale translation.
- **Sync guard.** `backend/tests/test_message_keys.py` checks that every template key appears exactly
  three times in `i18n.results.ts` (en, ru and kk), that the English there matches the backend
  template word for word, and that all three use the same parameters.

Nested keys: a parameter that is itself a keyed sentence carries `parts` (the requirement label
inside "No official minimum for {label}…", the requirement and explanation inside a knock-out, the
degree reason inside "Not applicable…: {degreeReason}", each missing category inside the
full-tuition reason, the label inside a conflict subject, the subject inside `conflict.why`).
`messages.ts` translates two more parameter kinds with the screen's own labels: `{axis}` (`axis.*`)
and `{classification}` (`status.*`). New helpers: `localizeAll(refs, english)` (all sentences or
the English, whole) and `localRequirement(label, checks)` for `hard_filter_failures`.

The Documents screen (`DocumentsScreen.tsx`) now goes through `t()` for every fixed label (owner
headings, meta line, completeness chip, calendar, notices) and `localize` for its open questions;
the lead time reuses `detail.docs.leadTime` (Russian plural). Checklist `ordered_steps` were already
rendered by `localStep` (owner, lead time and "after" said in the reader's language); they are not
re-keyed on the server because `localStep` handles the Russian plural a template cannot.

Coverage: the demo API test asserts every requirement check (label and explanation), award
classification, axis reason, bucket reason, knock-out and conflict in the demo carries a key, and
none is stored. Unit tests drive the real generators through every branch (`evaluate_program`,
`_check_numeric_minimum`, `_population_deadline_check`, `match_citizenship`,
`_scholarship_eligibility`, `classify`, `award_meets_shape`, `assess_degree_applicability`, each
`u_*` utility, `bucket_of`, `rank_result`, `_why_not_a_contradiction`, `find_conflicts`).

## Terminology

The results screens need words the glossary lists as Open. The words used are recorded as
**provisional** in `docs/i18n/GLOSSARY.md` and await review by a person who advises applicants in
each language. None is stronger than the English: "full ride" is "Полное покрытие" / "Толық
қамту", never "бесплатно". The fit is never called a probability or chance in any locale; a vitest
check enforces this.
