## Confirmed priority gaps

1. **P1 — a different signed-in person can inherit an unsaved local applicant draft.** [caseDrafts.ts:23–36,111–113,161–174](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/frontend/src/lib/caseDrafts.ts:23) keys envelopes by case only, without user/organization. [store.tsx:336–358](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/frontend/src/lib/store.tsx:336) restores a `local:*` pointer and its whole profile without a server ownership check. Sign-out ([App.tsx:393–395](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/frontend/src/App.tsx:393), [SettingsScreen.tsx:51](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/frontend/src/screens/SettingsScreen.tsx:51)) and account/workspace actions ([AccountMenu.tsx:54–59,75–80](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/frontend/src/components/AccountMenu.tsx:54)) reload but do not erase or namespace browser applicant data. Thus A creates a local case/edits → logout → B login in the same tab → native restore can display A's unsaved profile to B. Saved server-case pointers are separately protected by owned_profile/404, but that protection does not cover the local branch. [DocumentsScreen.tsx:24–49](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/frontend/src/screens/DocumentsScreen.tsx:24) also uses a single origin-wide docsDone map; no user/revision ownership is recorded. No exploit was executed.

   Smallest source increment: establish a browser applicant-data boundary from authenticated user+organization before StoreProvider hydration; clear/reject unowned legacy applicant slots on first authenticated adoption and owner transitions; preserve same-owner reload and explicit anonymous demo behavior. Clear applicant drafts/pointers/marks on successful sign-out/account deletion; leave theme/locale intact. Controls: A local draft→B, organization switch, same A reload, stale async replies, authenticated legacy slot must not import, logout failure must not falsely delete drafts, anonymous demo compatibility. Do not call origin-local marks durable/private server storage.

## Separate operational risk (no nginx change proposed here)

`frontend/nginx.conf:10–14` defines server security headers, while `location = /index.html:24–25` and `/assets/:17–19` define their own add_header Cache-Control. Under standard nginx header inheritance, local add_header suppresses inherited add_header directives; the main SPA HTML can consequently lack CSP/frame/MIME/referrer headers. API response CSP alone cannot protect a separately served HTML document. This is a source/configuration defect hypothesis with standard config semantics; deployed responses/installed nginx configuration have not been inspected. Minimal operational scope: header include applied at the relevant locations and a real isolated nginx route-header control for `/`, `/index.html`, SPA fallback, assets and API. Keep no-cache for index and cacheable hashed assets. Do not present current local native frontend tests as that header proof.

## Recommended order and limits

Do first the bounded browser owner boundary + honest case delete/export UX with native mock API controls; no backend checklist marks needed. Root can handle public policy/data-flow text in parallel. Versioned consent/minor flow requires an explicit approved server contract and legal input and should be a separate task. Nginx needs operational-header validation separately. Account-wide export/retention is a later bounded design, not bundled into the UI fix.

No fresh security/full/quality gate was run and no deployed behavior is certified. No actual breach, malicious content, third-party AI accuracy, jurisdictional compliance or production enabled recipients were inferred.
