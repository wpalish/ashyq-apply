# Хранение и запросы пользователя

Версия `2026-10-09.draft1`. Ниже раздельно наблюдаемый код и процедура, требующая внедрения оператором.

| Класс | Наблюдаемое поведение | Что надо утвердить и доказать |
|---|---|---|
| Профиль/исследование/чеклист | Пользователь может удалить case; основные связанные строки каскадируются | Максимальный срок по цели, automatic expiry при достижении цели, полный dependency graph и удаление/минимизация job payloads |
| Аккаунт/сессии/reset | Account delete и TTL сессий/reset; shared workspace остаётся | Учёт оставшихся платёжных/audit/операционных строк, атомарное использование reset token и необходимые законные исключения |
| Локальные черновики/отметки | Browser persistence; несинхронизированная подготовка | Изоляция владельца, очистка/недоступность при смене аккаунта, удаление соответствующих слотов и поведение quota/storage errors |
| Сообщество/переписка/жалобы | Разные join/leave/delete routes и доступ участников | Что остаётся у второй стороны/модерации, срок и правовое основание; не обещать blanket message purge |
| Платёжные записи | Учёт оплаты и entitlement | Необходимый законный срок, поля и дальнейшая минимизация; удаление кейса не равно стиранию бухгалтерской записи |
| Security audit/jobs/logs | Действия/идентификаторы/техническое состояние сохраняются отдельно | Состав/срок, исключить ненужный профиль в payload; права доступа; proof удаления и запрет бессрочного «на всякий случай» |
| Backup/replicas | Документирован backup script с default30 и исторический restore drill | Реальное расписание/место/шифрование/access/retention; дата истечения копии; deletion tombstones должны применяться до открытия восстановленной БД |

| Экспорты | Скачиваются пользователем | Предупреждение про локальные копии; оператор не может стереть файл на чужом устройстве |

## Экспорт, закрытие и удаление — разные результаты

JSON case record описывает конкретный case в рамках доступного API. Это не автоматическая полная выгрузка всех account/social/payment/operational данных. Сохранённый профиль без research run должен иметь доступные export/delete controls. Failed DELETE должен оставить данные и показать ошибку; сообщение об успехе допускается только после подтверждения API.

Закрытие account удаляет одиночные workspaces и оставляет общие для их других участников. Leave community не стирает весь account. Удаление профиля не доказывает очистку audit/job/backup или recipient copies. Ответ пользователю перечисляет scope выполненного удаления и конкретные оставшиеся классы с основанием и сроком, вместо «всё исчезло мгновенно».

## Обращение и проверка

Назначить ответственного и действующий privacy contact. Принимать просьбы о доступе, исправлении, ограничении, отзыве и удалении; завести номер и серверную дату. Проверять личность и полномочия минимально необходимым способом; обычный authenticated запрос не требует паспорта по умолчанию. Запрос представителя относится к подтверждённому субъекту, не к любому case в workspace.

Для каждого типа назначить применимый законный срок и внутренний срок раньше него, ответственного и escalation. Не использовать универсальное «30 дней» или «72 часа» для всех стран и операций. Зафиксировать ответ, состав выполненных действий, основания исключений и способ обжалования. Не складывать полный профиль в support-ticket.

Проверять на synthetic fixtures: zero-run case; API refusal; successful deletion and immediate remount/reload; shared organization membership; retained audit/job payload; export scope; backup restore into a new isolated DB followed by deletion replay before access. Подтверждения для ещё не реализованной полной retention automation сейчас NOT RUN.
