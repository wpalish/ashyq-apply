## Маленькая следующая задача перед durable backend

После принятия текущего full: **Find recovery + корректная Documents-подсказка**. В ShortlistScreen пустой результат сейчас показывает Start research и не читает текущий run state. ResultDetail ещё говорит «approve this row», хотя сбор поддерживает approved/maybe. Это две воспроизводимые source-находки, уже стоящие строкой «Затем» в [текущем product plan](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/docs/process/PRODUCT_COMPLETION_PLAN_2026-10-09.md:76).

Scope: эти два frontend места и несколько meaningful существующих тестов; использовать имеющийся onProgress/навигационный маршрут и native run predicates. Переданное stopped/partial состояние не превращается в отсутствие программы; когда callback отсутствует, остаётся честное объяснение без фиктивной кнопки. Controls: empty completed, stopped/stale, queued/running, отсутствующий run и maybe/approved choice; ни startRun/collect/decide/rerank не вызываются от показа или recovery. Не вводить автоматический retry и не пытаться снять provider STOP.

Это стоит сделать до backend progress: оно восстанавливает путь к уже сохранённым основаниям и существующей подготовке. Новая таблица отметок не исправит неверный следующий переход. Затем можно проверить сценарий результата 1/2 на сохранённых synthetic полях, а durable storage внедрять как отдельный owner/version increment.
