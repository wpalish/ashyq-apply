# Предварительный lifecycle review — без прототипа и выполнения

18 native файлов скопированы только после совпадения SHA с write-ahead PLAN. Manifest A ещё не поступил; executable controls не запускались. Это проверка границ сохранения routing evidence, не принятие правила или заявленный recall gain.

CatalogueDiscoveryAdapter.discover (86–130) сейчас ловит UniversityReadStopped, кроме checkpoint_busy, и оставляет исходный seed/trace. _enrich (132–159) получает enriched Candidate/Trace только после завершения _discover_one. LiveDiscoveryAdapter._discover_one (1154–1273) имеет отдельные локальные candidate/trace/selected и вызывает _apply только в нормальном завершении. _walk_catalogs сначала ожидает полного walker.walk; внутри walker.confirmation успешный URL уже может быть в локальном walk.confirmed, пока внешний selected его ещё не получил. Поэтому сохранённый факт успешного чтения может быть утрачен на последующем typed read_cap; callback перед следующим await — возможный bounded seam, но его корректность ещё не проверена.

ResearchRunner._stage_discover (742–780) присваивает self._candidates лишь после adapter.discover; отмена coroutine до возврата этого присваивания не завершает. Diagnostics discovery попадают в errors. Они не являются run.unknowns, Claim или отдельным durable source observation. Текущий saved Groningen outer asyncio cancellation остаётся вне предлагаемых гарантий: только callback в памяти не переносится автоматически в capture или SQL. В production нет показанного typed deadline emitter; synthetic UniversityReadStopped('deadline') этого не доказывает.

Если typed read_cap позволяет wrapper вернуть строго собственный ранее прочитанный provisional Candidate, обычный _stage_verify (786–1005) может создать ProgramResult и попытаться чтение. При исчерпанном guard _university_read_scope отказывает до нового get; _read_budget_unknown (671–692) добавляет явный run.unknowns и unresolved research read allowance. _persist_read_partial_result (694–721) сохраняет существующие факты при неполном перечитывании. Новые Claims из callback не следуют. Существующий native путь способен закончить обработку Run и Job с unknowns; succeeded означает завершение обработки, не подтверждение полного research. Новый proposal не должен фабриковать success при unhandled control/error.

SQL сохранение подчинено _save (210–267), _read_snapshot (588–620), _lock_read_checkpoint_job (557–585) и heartbeat attempt fence. Job→Run NOWAIT и SQLite pre-read write acquisition нельзя подменять memory callback. _stage_discover/_stage_verify checkpoint должен остаться fenced; obsolete attempt не пишет result/audit/counters. SQLite controls не доказывают PostgreSQL lock semantics. checkpoint_busy rollback не обещает durable unknown при занятой DB; Worker (152–161) оставляет восстановление lease reaper. RunCancelled/LeaseLost/asyncio.CancelledError не являются budget-result success.

Главный дополнительный риск: cloned snapshot снимается после подтверждения, но search later может зарядить ещё seam attempts. Candidate.search_queries_used устанавливается только _apply (1954), trace.search_queries_sent расходуется _remaining_search_query_budget (875–880). Нельзя возвращать замороженный ранний счётчик после последующих платных attempts. Ledger telemetry нужно обновлять из текущего trace отдельно от immutable facts snapshot, не заявляя HTTP dispatch и не вызывая _apply во время unwind. Strict wrapper способен скрыть такой production refund.

Ожидаемые самостоятельные controls записаны в expected-boundaries.json: wrong DS→CS, scope/year/population, multifield incomplete, latest charges, cap before unread get, both wrappers, propagation controls, actual Runner/SQL partial, complete whole-output equality и исключённый historical cancellation.
