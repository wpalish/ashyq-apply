**Минимальный seam: pipeline-owned university scope + wrapper вокруг созданного runner-ом `Fetcher.get`; durable envelope в существующем `ResearchRun.settings_snapshot`.** Ни один вариант часов ниже пока не считается выбранным owner-ом. Это внешний design/regression sketch, unreviewed; production source, Git и network не менялись.

Известный target DoD: **6 queries / 60 Fetcher reads / 120s на университет**, измеряемый isolated captures. Query implementation принадлежит отдельному обзору B. Current production Settings задаёт request timeout 20s, browser tier default on, candidate/verify limits 40/20 и renewable job lease 120s; university budget config сейчас отсутствует. Catalogue `discover` содержит 300s только на `_enrich`; evaluation strict capture вводит отдельные 60 cold get / 120s, включает setup и выключает browser. Предложение не поднимает 120 до 300 и не превращает lease в deadline. Новые cap constants 60/120000 должны иметь один production owner; expose произвольные увеличиваемые per-run Settings/API caps не требуется.

**Identity и scope.** Добавить один optional internal `Candidate.catalogue_id`; catalogue сохраняет `uni.id` и на исходном candidate, и на enriched return. Budget key = `catalogue:<uni.id>`, общий всем программам, intake requirements, costs/government и funding одного вуза в research episode. Не использовать programme key, URL host или `ProgramResult.university_id`: последний сейчас является normalized dedupe key, не ORM university ID. Curated fallback получает отдельный стабильный exact-name+country key (NFKC/casefold/whitespace, qualifier words сохраняются; hash), передаваемый через общий optional `research_scope` hook в `LiveDiscoveryAdapter`. Не парсить `discovery_source` для восстановления identity. Missing identity при guarded live read — fail closed, без provider/Fetcher fallback; demo fixtures сохраняют прежний путь.

Scopes: catalogue row **до** site identity lookup и `_discover_one`; curated entry до `_discover_one`; verification — существующий candidate/program work, включая req/cost/government, чтение/parse, result construction и persistence; funding — matched candidate/row, включая parse, result update и checkpoint. Повторное вхождение с тем же key не открывает новый бюджет. Разные вузы получают разные ledgers. Assessment без новых source reads остаётся вне source-work scopes; глобальные profile validation, catalogue retrieval и общие stage transitions отдельно записываются как run overhead, чтобы их отсутствие в university timer не выдавалось за совпадение с isolated capture setup time.

**Read charge.** Ровно один durable reservation **до каждого вызова original `Fetcher.get`**: cache hit, HTTP error, robots/privacy refusal, conditional GET и cold success расходуют одну единицу. `use_cache` не меняется guard-ом: production cache сохраняется, strict capture продолжает отдельно принуждать cold reads. После 60 reservations original get уже не вызывается. Reservation не возвращается после ошибки, cancellation, worker crash или recovery. Это строго upper bound допущенных get calls, а не доказательство 60 состоявшихся HTTP запросов: expose `calls_reserved` отдельно от actual outcome counters. DNS, robots, redirect hops, HTTP retries и renderer escalation внутри одного get не добавляют charge; все их ожидания расходуют scope time. Adapter memo и `gov_cache` reuse без нового get ничего не charge.

Government cross-domain get charge active university key; domain не определяет владельца budget. Существующие source/privacy/SSRF/robots проверки не меняются. Shared government page, прочитанная для первого вуза, может быть переиспользована со своими claims для второго без ещё одного get charge; второй вуз расходует время на собственную обработку reused evidence. Оригинал остаётся government source, не source университета.

**Два явных варианта времени (оба ≤120000ms, без скрытого расширения).**

| | A: absolute deadline | B: accumulated university-focused work |
|---|---|---|
| Timer | С первой university source-work scope до immutable deadline | Сумма monotonic elapsed всех scopes этого key |
| Что входит | Собственная работа, waits/rendering/CPU/checkpoint serialization, inter-university gaps, downtime | Все waits/rendering/CPU/checkpoint serialization **внутри** scopes; gap другого вуза и idle downtime вне scopes не расходуются |
| Multi-university effect | Ранний вуз может истечь до его verification, пока research работает над следующим | Discovery→verification→funding одного вуза делят 120s; работа другого вуза не отнимает allowance |
| Durable crash rule | UTC deadline плюс conservative remaining checkpoint; recovery не сдвигает deadline. Backward/unreliable UTC — abstain | При scope admission durably резервировать весь оставшийся time allowance. Healthy owned exit settles actual elapsed; незавершённая reservation после crash/reclaim **полностью расходуется**, не refund |
| Сопоставимость | Wall semantics близка одному isolated case, но shared staging добавляет чужую работу | University-focused semantics лучше multi-university staging; isolated setup/overhead всё равно требует отдельного accounting |

В независимом sketch A: U1 discovery 20s + U2 work 101s → U1 verification denied, 0 дополнительных calls. B при том же gap: U1 discovery 20s + verification 99s → 119s used, 1 get разрешён. Это измерение именно воздействия scheduling, не реальная site latency. Parent может выбрать semantics по evidence; report и метрики должны назвать выбранный вариант. Ни A, ни B нельзя молча выдавать за весь evaluation capture clock, который также включает setup.

**Envelope и существующий fence.** `stage_state` подходит только StageState dict: `RunState.load` пытается передать каждый dict в `StageState(**data)`. Не добавлять туда ledger. `settings_snapshot` — существующий JSON field; new namespaced `university_research_budget_v1` содержит version, episode ID, chosen clock policy, immutable limits и per-identity counters/time reservations/stop reason. Dates — UTC ISO или integer UTC milliseconds; active process monotonic timestamps не сериализуются. Validate types/nonnegative counters/exact configured cap; corrupt/incompatible envelope даёт unknown/diagnostic и 0 I/O, не новый бюджет.

При записи snapshot — **заменять весь dict и весь nested envelope copy**, не рассчитывать на SQLAlchemy tracking nested JSON mutation. `run_to_decision` сейчас перезаписывает snapshot; перед заменой copy сохранённого budget envelope и вернуть его в новый dict. Не сбрасывать funding/search state B отдельным writer-ом: один ledger mutator должен сохранять его opaque поля. `pages_checked`, stage counters и `fetch_tiers` не являются аналогами admitted get count; их не использовать для восстановления cap.

Guard сначала `_check_cancelled`, check remaining/count, записывает reservation, затем вызывает имеющийся `_save`: его heartbeat UPDATE conditioned on job+worker+attempt token и checkpoint commit находятся в одной transaction. **Только после успешного commit** original get допускается. В отсутствие fence / при `LeaseLost` rollback → 0 нового I/O. Устаревший worker не может refund focused reservation новым owner-ом. In-flight request старого worker-а уже был reserved и не даёт новому worker-у дополнительные единицы. Per-I/O append-only AuditEvent журнал — рабочая альтернатива, но сложнее/дороже, чем сохранение envelope: его восстановление потребует aggregation/journal replay. AuditEvent достаточно для summaries opening/stop/episode change; не дублировать каждый ledger counter в другом durable owner.

**Resume/episode.** Automatic recovery/retry **того же job ID** сохраняет reservations и выбранные limits/policy; смена `Job.attempts` — fence, не fresh allowance. Discovery сейчас повторяется даже при done stage, поэтому повторные get расходуют остаток, не новый cap. Старое legacy run без envelope получает явно зарегистрированный budget initialization; прошлые calls не объявляются задним числом compliant. Новый user retry создаёт новый Job ID; proposed episode boundary может быть этим ID, с сохранением предыдущего summary. Это должно быть named semantics (`per research episode`), а не незаметный reset per-run lifetime cap. Recheck является новым автоматическим job, documents — отдельным post-approval job: root должен определить их budget episode semantics и записать отдельно; draft не выдаёт им неявно свежий unlimited allowance. Direct runner без job использует stable `run.id:decision`, не random key на каждом constructor.

**Cancellation, unknown и сохранение facts.** Reuse `_check_cancelled` перед scope admission и каждым get, плюс прежние stage checkpoints. Не конвертировать `RunCancelled`, `LeaseLost` или внешний `CancelledError` в budget exhaustion. Scope remaining-time timer отменяет in-flight awaited DNS/robots/pacing/rendering/provider work; get wrapper сам не должен внедрять новый network retry. Budget reason — `read_cap` / `time_cap` / `unsettled_scope` / `clock_unreliable`, без vendor exceptions/URLs/applicant attributes. Run unknown text: `Remaining research remains unknown: the university research budget was exhausted.` Не использовать website timeout/robots/error vocabulary и не превращать unread facts в отсутствие programme/scholarship.

Catch typed BudgetStopped на university scope boundary; catalogue сохраняет candidate и trace limitation. В verify/funding оставить completed adapter outputs в caller-owned workspace **до следующего await**, затем собрать сохранённые claims и UnresolvedQuestion для unfinished topics; предыдущие persisted programme rows не удалять и evidence replacement не выполнять из пустого partial result. Факты, находящиеся только внутри cancelled adapter local variables, таким минимальным seam не сохраняются: это нужно честно отметить или добавить отдельный partial-output hook. В sitemap/walker broad `except Exception` явно re-raise typed control exceptions, иначе stop будет mislabeled как malformed sitemap/broken tier. Сохранять source outcomes, не маркировать budget denial как HTTP status или прочитанную страницу. Pure checkpoint/finalization после source-work deadline требует **резерва внутри 120**, не дополнительного allowance; допустимым sketch является явный finalization reserve, аналогичный evaluation reserve. Его размер/поведение root выбирает и измеряет.

**Две реальные границы минимального seam.** (1) `CatalogWalker._read_catalogue`, L670–683, вызывает renderer напрямую перед get. Timer его охватывает, но exact get-only counter его не считает. Strict capture browser off; production default on. Не называть standalone render «internal exchange одного get»: root должен либо сохранять точный get metric с отдельной render telemetry, либо объявить и измерить иной logical-source-read contract. Browser config в этом design не переключается. (2) asyncio deadlines cooperative: synchronous BeautifulSoup/CPU и sync SQLAlchemy `_save` могут завершиться после 120s, прежде чем timer получит event loop. Draft test намеренно показывает CPU completion на virtual 180s, затем budget stop. Он подтверждает no new reads после обнаружения, **не** hard wall enforcement CPU/serialization. Для строгого hard total wall bound нужен контролируемый process boundary/kill или bounded execution/DB deadlines; это выходит за claim простого wrapper и требует отдельной проверки. Final settlement commit также имеет latency: sketch не доказывает hard bound его собственной persistence.
