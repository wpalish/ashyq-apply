# Groningen DEV: confirmed identity удерживается за дополнительным discovery

Первый terminal case NEW LOCAL original10 baseline — Groningen — остановился по measured source deadline117007ms. Потеря относится к **BUDGET**, не к отсутствию программы или подтверждённому отказу classifier. На точных retained bytes official Computing Science классифицируется как Bachelor/Computing Science/English, общий programme predicate её принимает. Actual caller replay воспроизводит все первые32 URL reads в том же порядке и перед поиском имеет ровно один accepted programme. Curated registry entry исключает `_identify_site`; SI-1=False не является причиной этого case.

Фактический log: get28 Computing Science завершается около69s; затем читаются Information Science, Data Science & Society, Liberal Arts and Sciences и test.ucms Pedagogical Sciences (robots denied). Эти четыре чтения занимают суммарно20.5s по rounded individual duration logs. Затем search1–6, последнее до117s, и get33 homepage без return. Original observation URLs/ranked/predictions/page_outcomes пусты; full raw отсутствует честно. DB остаётся candidate_discovery, program_results/claims0. Это ещё не доказывает отсутствие извлекаемых требований/стоимости.

Обобщаемое минимальное будущее правило — **default False `WALKER_STOP_AFTER_CONFIRMED_SINGLE_FIELD`**: в текущем `CatalogWalker.walk_catalog` после `_read_lead` прекратить оставшиеся lead reads, если единственный distinct requested field уже подтверждён текущим programme predicate на официальном собственном programme page. `walk()` уже прекращает дальнейшие catalogues после confirmed result; этот же intent сейчас не действует внутри одного catalogue. Не увеличивать caps, не преобразовывать unknown/blocked/redirect/page-purpose failure в подтверждение. Multifield оставить по старому пути до отдельного корректного coverage protocol.

Внешний shadow использует неизменённые parser/scoring/classifier/predicate и retained bodies. Flag-off совпадает с whole frozen result и URL sequence. Alpha subcatalogue: 6 get (catalogue+5leads) → 2 (catalogue+Computing Science), тот же confirmed URL. Семь controls не дают early stop для wrong subject, wrong degree, пустого requested field, actual robots failure, multiple distinct fields, synthetic foreign redirect и actual other-page purpose. Source-патч не применялся; control exception существует только во внешнем replay для остановки исходного loop.

Caller boundary объясняет дополнительные6queries: `_add_search_results` прекращает поиск лишь после заполнения всех3 programme slots. Одно подтверждение для одного subject всё ещё оставляет2slots, поэтому programme-only search запускается до `_apply`/возврата `_discover_one`. В replay provider seam заменён no-op исключительно после сохранения этого input; при его завершении actual `_apply` переносит Computing Science в candidate. Actual provider candidate list/query texts неизвестны — отсутствующий raw не заменён пустыми search results. Это source-backed boundary proof, не end-to-end исправление production.

Предложение уменьшает подтверждённые лишние lead reads; оно не гарантирует, что оставшегося времени хватит на six-query search и verification/funding. Не предлагаются retries/provider swap, search snippets не используются как факты. Более сильное правило «не искать programme после покрытия subject» меняет alternative/campus/intake coverage и в этот минимальный proposal не включено.

Scope ограничения существенны. Classifier обнаруживает на retained CS page academicYear2026/27; это не подтверждает требуемый fall2027 и не переносится в2027 fees/deadlines/requirements. Предложение имеет только existing **degree/subject identity** contract. Его нельзя рекламировать как прекращение поиска после подтверждения всех requested intake/population/campus/language scopes. Wrong-target-year/campus/population immunity этими controls не доказана; при требовании такого stronger contract эксперимент не готов к применению, пока source-backed scope coverage не определено. Никакого university/acronym hardcode в условии нет.

Самая ранняя access loss в log — get3 sitemap shard `too_large`; тела shard нет и число пропущенных URLs неизвестно. Global discovered→unique count и provider result count остаются unknown. Из log известны33 get admissions,20 distinct exact requested URLs,32 returns (30ok/1too_large/1robots), один incomplete get,56 page HTTP requests и6 provider-seam queries. Retained alpha catalogue локально даёт159 canonical unique same-institution links,85 scored leads и5прочитанных leads; это отдельный локальный replay, а не весь production discovery funnel.

Перед любым source изменением сохраняется parent freeze всей live queue.
