# LOCAL controller v1: validation blockers до исполнения

Проверен только офлайн source/validator; `main`, `--execute`, subprocess, DNS, сеть и STOP writes не запускались. Исходный controller сохранён как `local_pilot.v1.py`, SHA-256 `8497443b97a6a51db3d2225d716e7cbcc2f17dc2b7ab8772177cad757e8dcf90`. Его байты совпали с root v1. Prepared snapshot: head `7277c154bda838688268b7a07d4286ed8f4688ce`; 3410 declared file hashes совпали, executable subset совпал с prepared full-check manifest. Git не вызывался; HEAD/status утверждения main рассмотрены как code checks, не independently executed Git proof.

Синтетические tests: **23 failed, 8 passed / 0.11s**. Это contract failures validator, не production university/quality evaluation. Cap counter guards корректно отвергают bool, -1, 61 reads, 7 queries, elapsed120001. Completed capture без raw отвергается; bounded internal source deadline с отсутствующим full raw отмечается честным отдельным флагом. Подробный raw log сохранён.

Материальные findings:

1. Full raw проверяется только `is_file`. Empty/invalid JSON/{} /[] и raw другого case принимаются. Physical `.budget.json` не читается: отсутствие либо counter61 в нём не мешает успешной validation, если Capture.config выглядит правильным.
2. Объявленные max/strict/reserve/deadline и terminal process/provider markers в budget могут отсутствовать; mode=fixture, missing telemetry и contradictory `stop_reason=http_429` без failure envelope/batch marker принимаются. Это позволяет считать protocol-incomplete capture completed, не подтверждая declared local/cold/zero-model provenance.
3. Malformed config/observations дают AttributeError/TypeError вместо structured result. `main` не ловит эти ошибки вокруг read/validate и прекращается до сохранённого protocol-stop/finish summary. Будущие case не запускаются, но outcome/remaining-case audit остаётся неполным.

Фактический старый raw schema проверен по field shapes, без gold/labels: `{canary: {accessed_at,duration_seconds,run_error,batch:[university names],institutions:[rows],totals}, claims:[Claim payload]}`. Row identity — nullable catalogue_id плюс institution/country/domain; URLs находятся в `programs`. Raw claims имеют `claim_type` и `source_url`. Child physical budget содержит schema/config/counters/timing/stop_reason/provider_failure; parent добавляет в Capture.config ещё `parent_process_elapsed_seconds`, `process_error`, `active_checkpoint_available`. Сравнивать следует обязательные child keys/subset с capture, а не весь parent budget dict с child JSON.

Argv reconstruction соответствует existing prepared command: ten original cases sequential, `--live --strict-expert-budget --max-pages 60 --seconds-per-case 120 --search-provider exa_mcp --shared-query-budget`, новый stop-file и reserve3000. Новый source work deadline117000 задаётся strict harness, не дополнительным запросом/обнулением. Алгоритм/provider/source не меняются. Safe_env из package очищает UNIMATCH variables/known secret names и указывает isolated runtime. `Run.step` локально запускает один process group; strict live parent имеет собственный child subprocess timeout. Сам package `Run.step.wait()` outer timeout не имеет: hard bound всей startup/outer-controller жизни этим review не доказан.

Source hashes проверены до всей queue и после всех десяти; per-case byte freeze внутри queue не проверяется. При действительно immutable owned snapshot это не наблюдённая потеря; обычная concurrent mutation такого snapshot не доказана. В случае stronger freeze contract полезно повторять hash-check до каждого нового dispatch. Новый sentinel проверяется перед каждым case и после возвращённого шага; старый CI STOP сравнивается по immutable SHA. Provider wrapper создаёт новый STOP на vendor failure. Для повреждённого/отсутствующего sentinel fallback по явному physical provider refusal рекомендован отдельно; website HTTP failures не должны превращаться в provider stop.

Родитель получил findings до исполнения и сохраняет v1/plan неизменными; новый v2 рассматривается отдельно. Ни один из этих тестов не является разрешением live запуска или оценкой качества поиска.
