# Genuine research Job protocol: evidence-only plan

Статус: PROPOSED / NOT IMPLEMENTED / NOT EXECUTED. Это план будущего измерения, а не launch acceptance или доказательство production 6/60/120. В этом раунде нет сетевых вызовов, запусков pipeline, новых SQL controls или изменений приложения. Точные прочитанные байты и AST anchors записаны в source-inputs.json. Исторические Worker и PG receipts сохраняются отдельно; их результаты не являются результатами предлагаемого canary protocol.

## Подтверждённый исходный путь

backend/scripts/canary_discovery.py:397 run_canary создаёт новый temp SQLite и synthetic Organization/Profile/ResearchRun, но лишь flush перед исполнением. На строке466 создаётся CanaryRunner(session, run, profile, settings) без job_id/worker_id/lease_token. Нельзя назвать этот путь fenced, добавив произвольные ID или вручную строку RUNNING. FetchAudit группирует завершившиеся reads по домену URL, а не по university budget key; government reads могут оказаться в другом домене.

backend/app/jobs/worker.py:112 execute открывает собственную session_scope, создаёт настоящую heartbeat task и вызывает _dispatch; _dispatch передаёт в ResearchRunner реальные job.id, worker_id и attempts lease_token, завершает Job через условный complete и пишет job_completed audit. Worker сегодня в репозитории остаётся original49...; reviewed typed checkpoint_busy Worker proposal e6... находится внешне. Его применение — отдельная предпосылка robustness, не часть скрытого fake patch для измерения. Readguard v2 тоже пока external. По текущему source такой новый protocol ещё нельзя запускать или объявлять green.

JobStore.enqueue:90 и claim:146 уже дают нужные операции. enqueue возвращает созданный QUEUED Job; claim меняет status и увеличивает attempts, его commit обязан предшествовать I/O. worker_identity:40 — настоящий host:pid текущего child. В v2 university ledger episode — decision:<Job.id>, budget identity берётся из фактического Candidate.catalogue_id либо нормализованных name+country. Не подменять её case id или URL host.

## Минимальные владельцы и функции

Изменить только backend/scripts/canary_discovery.py и backend/evaluation/research/live.py после разрешённого parent checkpoint применения readguard/Worker. Не менять Settings, JobStore, Worker lifecycle, общую Fetcher архитектуру или миграции ради capture. Новые tests: backend/tests/test_canary_fenced_job.py и backend/tests/test_readguard_capture_protocol.py. Имена следующих private helpers — предложения, их ещё нет в source.

В canary новый keyword-only fenced_research_job=False у run_canary; legacy body остаётся прежним и ветвится в отдельный _run_fenced_research_job для opt-in. Его маленькие вспомогательные функции: _canary_session_scope(local_factory), _snapshot_job_protocol(fresh_session, job_id, run_id), _finish_fenced_case_cleanup(...). Все sessions принадлежат уже созданному per-case engine; никакого app.db.SessionLocal/default connection или project database. Перед enqueue commit synthetic Organization/Profile/Run и каталог, закрыть setup session. В fenced ветке начальная выборка обязана содержать ровно одну реальную resolved identity. Standalone batch без новой опции остаётся legacy.

_run_fenced_research_job должен использовать настоящий Worker.execute и _dispatch. В пределах одного isolated child допустим scoped patch worker_module.session_scope на local factory context и worker_module.ResearchRunner на subclass текущего canary.CanaryRunner, удерживающий pure audit/candidates/traces для отчёта. Именно текущего класса, а не сохранённого до live.ObservedRunner binding. Это локальные подключения к реальной реализации, а не замена claim/fence/checkpoint на mocks. Конструктора Worker(worker_id=worker_identity()) достаточно; JobStore.enqueue('research', run_id=..., unique canary idempotency key) затем реальный JobStore.claim(worker_id=worker.worker_id), assert exact new job.id / attempts==1, commit. Использовать ровно одну execute; не запускать run_forever, автоматический retry/reaper или queued recheck. Их возможное создание и окончательный status честно фиксировать.

Capturing subclass run_to_decision ловит BaseException лишь для сохранения исходного типа/reason и снова raises; он не превращает ошибки в успешное return. Worker обрабатывает success/cancel/LeaseLost/error как настоящий production caller. jobs_done/jobs_failed — вспомогательная телеметрия, не доказательство terminal state: fresh SQL snapshot проверяет настоящий Job. Результаты/claims/run/page metadata после закрытия worker session прочитать из НОВОЙ local session. Pure audit/traces не требуют detached ORM. Прежний gather можно выделить в helper с нужными значениями, но нельзя читать run relationships после close или отключать lease ради отчёта.

В live.capture_one добавить fenced_research_job=False как новый explicit keyword; старые вызовы canary/kwargs при False сохраняются. Локальное runtime присваивание read_budget.UNIVERSITY_READ_BUDGET делается child до создания runner; source constant остаётся False. В main parent+child две опции BooleanOptionalAction: --university-read-budget/--no-university-read-budget, --fenced-research-job/--no-fenced-research-job. Для readguard omission default берётся из source module (сейчас False); последнее явное значение побеждает. Не применять OR с module flag: explicit False обязан отключать даже при враждебном исходном True в control. Child argv всегда содержит явный readguard bool и fenced bool; parent config использует те же resolved значения. Standalone canary также принимает эти flags и применяет runtime bool scoped до исполнения. Module-off default не повышается.

## Обязательные проверки до source I/O

Guard=True требует fenced=True, включая прямой capture_one и standalone API; unfenced guard-on не пытается работать с fake Job. Fenced=True, Guard=False разрешён: обе стороны сравнения используют один genuine Job protocol. Нельзя автоматически включать fence только в on arm.

Новый fenced mode первоначально отказывается от --check-seeds и D7 --with-documents (в прямом API также от уже установленного DOCUMENT_SECONDS). check_seeds — отдельный noJob Fetcher path. documents_stage сейчас повторно использует runner после research decision; completed research Job не может честно ограждать новый documents stage. Это bounded initial scope, а не отмена legacy D7. Future documents measurement потребует отдельного настоящего documents Job и нового protocol.

Catalogue parent batch допустим как последовательные отдельные child cases, каждый из которых разрешает ровно одну identity и новый SQLite. Unknown/no-domain/duplicate IDs, неоднозначный registry selector, fenced direct no-selector или multiselector отвергать до Fetcher/provider. Current curated selector может пройти через импорт каталога: фиксировать реально выбранный Candidate key, а не предполагать curated key по входному домену. Одинаковые правила в standalone, direct capture API и CLI.

Existing STOP semantics сохраняются. Provider/auth/quota/refusal останавливает весь batch; следующий case не spawn/enqueue/claim. Ни один leased Job не оправдывает provider retry, swap или purchase. PreSTOP envelope записывает intent flags, attempted/remaining case IDs и actual_job_status=not_started; Job.id/lease token/ledger отсутствуют. Не создавать фиктивное zero-ledger доказательство для неисполненного case.

## Checkpoints, cancellation и observation

Начало strict active clock остаётся первым capture_one entered=time.monotonic. Setup SQLite/import/catalogue/enqueue/claim/checkpoints/CPU/serialization/waits входят в тот же case clock, без reset на enqueue или первом read. Existing finalization reserve и parent hard timeout не увеличивать. Native v2 guard сам ограничивает reads, не время. SQLite writer wait и любые synchronous DB operations могут пережить asyncio cancellation; не выдавать локальный protocol за hard120 cap.

В fenced live.ObservedRunner finally нельзя безусловно выполнять current self.record_claims() на Worker session. Он делает SQL, способный заменить исходный typed checkpoint_busy/LeaseLost новой observation ошибкой. Новая ветка сохраняет pure page outcomes/exception, после Worker cleanup mapping claims читает fresh local Session. При timeout/deferred busy этот reporting best effort фиксирует observation_unavailable и свежесть последнего durable/checkpoint, не маскирует исходный control и не записывает unknown/failure через contended ORM. Legacy unfenced finally/claims mapping остаётся прежним. Отдельный отрицательный control обязателен: исходный typed busy остаётся typed даже при observation query refusal; никакого secondary writer и source IO.

Heartbeat task finally отменяется и await-ится в локальном helper cleanup (реальный _beat, а не fake counter); все локальные sessions закрываются и engine.dispose вызывается. Доказательство stopped task фиксируется отдельно от guarantee отмены уже заблокированного синхронного SQL, которого здесь нет. При успехе Job succeeded с token1 и job_completed; ordinary fail остаётся queued/backoff или failed по настоящим store правилам. При RunCancelled — реальный cancellation outcome. При LeaseLost — новый владелец защищён и старый ничего не финализирует.

Если outer measurement deadline отменил waiting mock pipeline, не выдавать job success. Когда БД доступна и token всё ещё принадлежит этому worker, helper может сделать real fenced mark_cancelled с отдельным measurement_deadline reason, сохранить ledger/prior facts без refund. Если БД занята — running/deferred, cleanup_unknown, последнее доказанное состояние; никаких немедленных retry/failure-writer loops. Hard-killed child может не выполнить finally: parent пишет killed/last_checkpoint_only, а не completed. Reaper recovery проверяется offline после снятия lock и фактического expiry, не исполняется в capture за счёт нового source budget.

## Provenance и четыре arms

Новый protocol name например canary_genuine_research_job_v1. Capture.config ordinary и preSTOP хранит university_read_budget: bool, fenced_research_job: bool, protocol version и source/harness/mapping hashes. Эти intent fields не заменяют execution proof. Canary raw report содержит job_protocol только при fenced=True, чтобы legacy raw off shape не менялся. Per-case .job.json атомарно содержит actual enqueue-created/claimed/token/worker/status, run/job IDs, effective runner guard, episode ID/read_counts из fresh SQL, source checkpoint availability и terminal/deferred/cleanup_unknown. Во время checkpoint брать доступные факты; на refusal не фабриковать финальный ledger. Только synthetic DB; не экспортировать env/provider keys/DB secrets.

Три разных меры сохраняются независимо: strict outer Fetcher attempts, actual original Fetcher outcome/audit и committed native read ledger. ObservedRunner.bounded before_fetch стоит СНАРУЖИ native before_get: stale fence/busy после outer charge допускает wrapper attempts > native admissions; scope refusal может произойти раньше outer charge. Cache strict cold setting и native cache charge описываются отдельно. Domain FetchAudit не суммируется как university ledger: government cross-domain get внутри текущей scope тратит текущий университет. Native счёт — каждый BudgetedFetcher.get включая cache/error/robots outcome; внутренние HTTP/robots/redirect exchanges не добавляют вызов get. Query ledger/time/docs/recheck guard excluded. Превышение off61 доказывать offline без outer strict60, иначе harness маскирует отсутствие cap.

Для новых off/on/on/off всех четырёх arms фиксировать fenced=True, одинаковый source/protocol/settings/selectors/global feature flags, новый isolated SQLite и новый claimed Job token1 для каждого case в каждой arm; меняется лишь requested readguard bool. При новой базе не существует pre-existing recorded-on episode. Если SI-1 нужен для достижимости institution, он одинаковый во всех arms и явно отражён; это комбинированный эксперимент. Прежние20 unfenced captures не переписывать и не объявлять новым эквивалентным baseline. New intent bool off не означает универсальное отключение recorded-on existing Job при resume; v2 уже честно сохраняет такое ON intent.
