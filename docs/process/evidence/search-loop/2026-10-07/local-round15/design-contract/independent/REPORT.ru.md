## 1. Два разных бюджета должны иметь два явных происхождения

Алгоритм сохраняет физический capture **120 секунд / 60 Fetcher.get / 6 поисковых попыток**. Независимый эксперт получает **60 чтений / 6 запросов**, без дополнительного 120-секундного активного ограничения; **900 секунд WALL** — защитный срок, который включает размышление, хотя размышление исключено из исследовательского elapsed. Эти результаты нельзя обозначать как равный 120-секундный baseline intervention.

В текущем коде strict controller отвергает max_ms=900000 до I/O ([controller.py:389](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/backend/evaluation/research/expert/controller.py:389)). `validate_trace` требует равенства бюджета trace и `packet.baseline_budget` ([models.py:779](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/backend/evaluation/research/expert/models.py:779)); raw budgets и tool_policy должны совпадать с trace ([models.py:690](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/backend/evaluation/research/expert/models.py:690)). Нативные проверки подтвердили оба отказа. Одна замена числа в старом плане недостаточна.

Минимальный явный режим `expert_wall_only` должен связывать packet, trace, controller policy/budgets, summary и resume: independent_full_budget; точно 60/6; nullable активный предел только при выбранном режиме; защитный WALL=900000. Алгоритмический capture остаётся отдельным неизменённым входом с собственными hash/caps. Отсутствующий/неизвестный режим или просто None не разрешает обойти лимит. Legacy режимы и сериализация сохраняются. Это требует equality исходных model_dump bytes и canonical digests: новый default clock field может изменить hashes даже при прежнем поведении. Старые fixtures не регенерируются. Cross-mode packet/raw/trace/resume и wall-only под видом baseline_intervention должны отвергаться; эти будущие gates пока не исполнены.

Original per-case wall anchor/deadline создаётся один раз по документированному началу эпизода и сохраняется; очередной turn или resume не начинает новые 900 секунд. Оставшееся WALL время ограничивает **фактические** model/source dispatch. Измеренное размышление фиксируется отдельно, исключается из исследовательского elapsed, но не вычитается из защитного WALL. Важно проверить реальное использование этого режима в orchestrator, а не наличие невызываемого helper.

Старый selector имеет потолок 55 секунд ([selector.py:45](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/backend/evaluation/research/expert/selector.py:45)); нативная проверка сохранила этот отказ без запуска CLI. ## 3. Complete, partial и unrun выводятся из оригиналов

Complete требует успешного последнего original model submit, совпадения final JSONL message с exact last-output file, принятого whole journal и `processed_through_action_count == len(recorded_actions)`. Native `selector_answer` отвергает error/turn.failed, неполный lifecycle и tool events ([blind_cli.py:182](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/backend/evaluation/research/expert/blind_cli.py:182)); контроль неуспешного потока подтвердил отказ. Поля `completed=true`, `isolated=true`, `neutral_pass=true` сами по себе не доказательства.

При финальном отказе сохраняется **предыдущая** accepted snapshot: receipt partial, без заявления о завершённом submit. Модельная попытка без source actions — attempted partial/no-source, а не unrun: текущий ExpertTrace требует минимум одно действие ([models.py:206](/Users/wpalish/Documents/Codex/2026-10-07/x20/work/ashyq-apply/backend/evaluation/research/expert/models.py:206)), и нельзя изобретать действие ради схемы. Unrun означает отсутствие process/model/source попытки с точной причиной. Сайтовые robots/404/timeout и местный исчерпанный бюджет дают unknown/inaccessible, а не отсутствие программы/условий.

Алгоритмическая receipt проверяет физические capture/observation/budget/raw, job/protocol/caps/source и причину partial. Exit0 subprocess не гарантирует пригодный результат: physical budget/raw provider_failure может быть fatal даже при exit0. Алгоритмическая и экспертная receipt должны иметь отдельные clocks/counters, но точное соответствие одного публичного canonical case. Детали нового actual algorithm validator ещё не рассмотрены.
