# KB end-to-end smoke, 2026-10-19

This smoke test checks that the product works end to end in the default `UNIMATCH_KNOWLEDGE_MODE=kb`, the
way an applicant would see it. It ran the real API, the real job worker, the real Vite frontend and
headless Chromium against a scratch SQLite database. It made no search-provider calls, read no pages and
made no paid calls. KB version: `2026-10-19.kb-cs-bachelor.5` merged with `kb_imported_dev.json`.

## Setup

| piece | how |
|---|---|
| API | `uvicorn app.main:app --port 8099`, run from `backend/` |
| worker | `python -m app.jobs.worker`, a separate process as in production |
| env | `UNIMATCH_DEMO_MODE=false` (the setting defaults to `true`, see G9), `UNIMATCH_KNOWLEDGE_MODE=kb`, `UNIMATCH_SEARCH_PROVIDER=none`, `UNIMATCH_ENABLE_BROWSER_TIER=false`, and `UNIMATCH_DATABASE_URL` / `CACHE_DIR` / `EXPORT_DIR` pointing at a scratch dir, never `backend/data` |
| network guard | A `sitecustomize.py` on `PYTHONPATH` wrapped `socket.connect`, `connect_ex` and `getaddrinfo` in both processes. It logged and refused every connection that was not to loopback. `HTTP(S)_PROXY` pointed at a dead port as a second fence. A probe confirmed the guard was loaded. |
| frontend | `vite` on :5173, which proxies `/api` to :8099. Playwright 1.62.1 drove `/opt/pw-browsers/chromium` and aborted every request that was not to localhost. |
| profile | Bachelor's, `intended_fields=["computer science"]`, fall 2027, Kazakhstan citizen, IELTS 7.0 (writing 6.0), budget USD 20,000. A copy with `["law"]` made the out-of-scope profile. |

The steps:

1. Created the profiles through the API: `POST /api/profiles`.
2. Started the runs:
   - through the API, with `POST /api/runs` and the `university_ids` taken from `/api/universities?q=`;
   - through the UI, on Find → "Explore more universities from the local catalogue", by ticking 5
     universities and pressing "Research selected (5)".
3. Read the results through `/results`, `/summary` and `/questions`, and in the UI through the shortlist
   cards and each card's Requirements, Funding, Costs and Sources & evidence tabs, plus the Funding and
   Sources screens.
4. Approved MIT and Edinburgh and ran `collect-documents`.

## What works

- **No outbound traffic.** The network guard logged 0 blocked connections across 7 runs, a document
  collection and the UI sessions. Every run shows `pages_checked=0`, fetch tiers all 0, and
  `settings.knowledge_mode="kb"` with the KB version. The browser recorded 0 external requests.
- **Claims cite official URLs and quotes.**
  - Every KB claim has `official_domain=true`, confidence 0.8, the verified quote as its excerpt and a
    clickable link to the official page, for example
    `mitadmissions.org/apply/firstyear/tests-scores/` and
    `study.ed.ac.uk/.../57-computer-science/entry-requirements`.
  - The UI "Sources & evidence" tab renders each claim with its quote and link.
- **Stale facts are never current.**
  - MIT's 2026/27 tuition (USD 66,720), KTH's SEK 453,000 per programme and FU Berlin's EUR 0 policy
    are `POSSIBLY_STALE` with `is_stale=true`, and the reason is in `notes`.
  - None of them enters the cost table, so the gap is "not computable" rather than computed from last
    year's fee.
  - ETH's CHF 2,190 per semester says "Amount per semester, as published; not a yearly figure".
- **Funding from KB awards.**
  - MIT gets "MIT Scholarship" and Edinburgh gets "Global Talent Fund BIG Scholarships". ETH's
    need-based aid is classified `UNKNOWN`, with "international students eligible / Met", the quote and
    both source links on the Funding tab.
  - Amount and coverage say "not published"; nothing is invented.
- **(c) and (d) block honestly.**
  - Groningen gets the blocking question "No verified data yet for University of Groningen: the
    bachelor's in Computer Science."
  - Law at MIT and Edinburgh gets "No verified data yet for …: this programme (the knowledge base
    covers only the bachelor's in Computer Science)", with 0 claims and a blocking question.
- **Ranking and buckets render.**
  - Edinburgh, KTH and MIT are `AMBITIOUS`: eligibility MET, coverage 0.21.
  - ETH, FU Berlin and Groningen are `NEEDS_CLARIFICATION` with sort key 0.
  - The UI shows the "Ambitious / Met / Unknown" and "Needs clarification / Unverified / Unknown" chips.
    No percentage or "chance" appears.
- **Documents.** Approved rows get "What documents does … require …? The verified knowledge base does
  not hold document lists yet …". The run completes with no errors.
- **Golden demo is unchanged.** `seed_demo.py` (demo mode, scratch DB) printed the same table on HEAD
  and on this change. The output is identical apart from the profile and run ids: Groningen #1
  (FULL_RIDE_CONFIRMED, 0.79), UBC in the table at FULL_TUITION / 21,471 USD.

## Environment notes (not product bugs)

- When the worktree's `frontend/node_modules` is a symlink to the main checkout, Vite answers some asset
  requests with 403: the file allow-list excludes a path outside the root. The page still renders.
- `pkill -f app.jobs.worker` from a shell whose own command line contains that string kills the shell
  first. Kill the worker by pid. An old worker left running picks up new jobs with the old code.

**Runs.** The applicant is the CS-bachelor profile above: Kazakhstan, IELTS 7.0, USD 20,000. It was run
