# G2 integration decisions before source proposal

2026-10-12. **READ-ONLY DECISIONS / NOT_APPLIED / NOT_RUN.** G1 still owns the active PostgreSQL runtime. Accepted typed/persistence v2 stay unchanged; these decisions bind their later integration to current native seams. Root read `proposals/g2-design/G2_IMPLEMENTATION_DEPENDENCY_MAP.md` (SHA-256 `47b21ed69e2ab087bae7d6d8820e316cba852e35d089f2d64db6876aa57a7210`). New HANDOFF/task branch and terminal G1 release are prerequisites for code.

1. **Reuse G1 source assembly in process.** Prefer an explicit adapter calling the existing `preparation_graph` route function with real owned profile ID, exact ordered IDs, principal and the current Session supplied explicitly. There is no HTTP self-call, Query/Depends default reliance, parallel source loader, direct network or copied evidence algorithm. Current G1 source stays byte exact. Saved reads probe safe per-goal owned metadata first, then request G1 only for eligible/currently authorized goal slices. Compare per-goal safe reference digests; an overall one-ID graph fingerprint is not the saved whole-selection fingerprint.

2. **Validate own reviews with the actual receipt seam.** Use current `review_attempt` semantics and owned `StudyAttempt` lookup, comparing exact attempt UUID/lesson/version. A held old-version receipt can be reviewed with `lesson=None`; do not require current catalogue membership or reuse the stricter v2 calendar save validator. A sample of the latest 20 attempts is a display list, not a complete ownership check. The frontend reuses `PreparationCase.openLearningTarget`.

3. **Legacy concurrency remains a source-proposal gate.** Before claiming technical preview→save CAS, propose and test a transaction strategy for existing and absent `StudyScheduleRow` on SQLite and PG. A single earlier read is insufficient. A present legacy row may be locked and rechecked; absent-row behavior needs a verified ordering/locking mechanism. Profile official data, `updated_at`, legacy settings/ticks and private helper guards may not be mutated merely to obtain a lock. Keep the broader research-writer observed-manifest caveat. Do not reduce this to a mocked same-session check or claim a cross-writer atomic guarantee without the real two-session controls.

4. **G2 mounts independently and contains one budget.** No v1 row or full one-exam target_scores are required to enter the opt-in route. Targets remain optional personal fields. First increment does not import legacy sidecar refs automatically; imported-ref anchor is null until an explicit supported import exists. Saved exact allocation/history is never regenerated by GET or by opening the panel. Preparation term and research display entitlement remain independent. G2 save ACK selects that saved shared route for future Today; legacy read/history preserves its own API and cannot silently add another workload.

5. **Programme candidate scope must be explicit.** Existing UI offers results of the case's latest run. The later G2 panel may use those owner-fenced candidates and separately restore the exact saved selection through its owned server GET, including older-run selected IDs with currently authorized labels/status. It must not reject or erase a saved selection merely because it is absent from the latest-run prop. Label the source of newly offered candidates explicitly. A complete historical candidate browser/pagination is a separate expansion; local card names or general export are never ownership/source authority.

6. **Current state and safe receipt are distinct.** Full accepted reference-only allocation is stored identically in current/history/PUT/replay and exported. Source names, claims, scopes, dynamic needs_review and premium details remain current read projections. Missing/foreign, decision_changed, research_locked, source_changed, malformed/unknown content and preparation expiry are separate reasons; a locked GET cannot reveal a newly computed premium digest. Existing profile export policy remains unchanged.

This document supplies no implementation/test/lock proof, migration or runtime permission beyond the pending later task. Exact preimages and actual allowlist must be recorded again before any source proposal.
