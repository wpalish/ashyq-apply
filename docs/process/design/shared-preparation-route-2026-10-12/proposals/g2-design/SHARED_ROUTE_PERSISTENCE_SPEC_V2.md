# G2 v2 — сохраняемый общий маршрут с безопасным receipt

**12.10.2026 · G2_DIRECTION_ACCEPTED_DESIGN_ONLY · PERSISTENCE_CODE_NOT_READY · NOT_APPLIED / NOT_IMPORTED / NOT_RUN.** Самостоятельная версия спецификации после [G2_DESIGN_REVIEW.md](../../G2_DESIGN_REVIEW.md). Исходный `SHARED_ROUTE_PERSISTENCE_SPEC.md` сохранён без правок. Это контракт для root review, а не source proposal, миграция или выполненная проверка. Область ограничена собственными выбранными программами, личным выбором подготовки, существующим exact-version catalogue и одним общим бюджетом времени.

## 1. Семантика: выбор, доказательство, сохранение

G1 остаётся read-only авторитетом для полной **новой** ordered selection собственных `approved`/`maybe` результатов. Его `family_only` workstreams не доказывают accepted route, edition, AND/OR, waiver, совместимый numerical minimum или admission outcome. Пользователь может **явно** выбрать личную подготовку к IELTS Academic и/или Digital SAT, указать плановые даты, timezone, study days и один недельный budget. Такой выбор можно сохранить как *applicant planning input* при `programme_applicability=unknown`; UI не называет его обязательным требованием вуза. Другие exam families без реализованных exact-version материалов имеют честную `no_content`/unallocated ветвь.

Первый G2 increment сохраняет только personal practice route и общую capacity. Admission и scholarship atoms остаются отдельно видимыми через текущий разрешённый G1 GET; в G2 нет `proven_exact` cover edge, merged numeric target или accepted waiver, пока отдельный typed evidence/operator gate не докажет relation, purpose, route/edition и exact scope. Отсутствующий или противоречивый proof даёт `unknown`, а не выбранный максимум. Source recheck идёт только действующим разрешённым research path; G2 GET/preview не делает сетевого исследования и не меняет original checks.

## 2. Три различных представления данных (D1)

### A. Неизменный принятый write receipt

`SharedRouteWriteReceiptV1` — единственный body успешного PUT и его idempotent replay: `schema_version=shared-route-v1`, own `profile_id`, accepted `revision`, `client_write_uuid`, canonical request digest, accepted UTC time, ordered selected result IDs, **личные** confirmed exam choices/planning inputs, pinned exact content refs, generated action/slot IDs and minutes, saved budget, source **reference digests/fingerprint**, catalogue/planner versions и snapshot digest. Он не содержит G1 university/programme name, source excerpt, claim, checklist, raw requested scope, premium current status, entitlement flag или динамический `needs_review`. Persisted current/history rows хранят этот reference-only receipt/snapshot. Исторический receipt не изменяется при recheck, expiry или source supersession.

### B. Current/history GET view envelope

`SharedRouteViewV1 = { receipt, current_status, visible_evidence }`. `receipt` всегда совпадает с принятым immutable receipt. `current_status` вычисляется заново: per-goal `eligible/decision_changed/result_unavailable/research_locked/source_changed/evidence_unknown`, структурный legacy status, content availability, `needs_review` reasons и `as_of`. Это **response projection**, не новая запись и не изменение receipt digest. `visible_evidence` берётся только из **текущего** разрешённого G1 read per eligible slice. При locked/expired research entitlement — только фиксированный locked receipt; исторические premium names/proofs не достаются из cache/сохранённого тела и не обогащаются локальными result cards. Preparation term expiry сам по себе не означает утрату research entitlement: разделять `preparation_access` и `has_full_access`.

### C. Own export и delete

Экспорт G2 содержит current reference-only receipt, все принятые reference-only history receipts и applicant action events, с typed digests/provenance; **не** добавляет исторические premium copies. Остальные существующие `results`/`claims` в общем profile export следуют действующему owner-only export контракту, который уже возвращает собственные записи независимо от case research display entitlement; G2 не меняет и не переопределяет этот маршрут. Такое различие явно указать в export note. Delete own case удаляет G2 current/history и existing schedule/attempt rows; sibling case нетронут. Это выбранное правило хранения/export G2, не неподтверждённое обещание изменить общую export policy.

PUT после настоящего commit всегда возвращает **только immutable receipt** с одинаковой семантикой 200 для первой доставки и retry. Если клиенту нужен актуальный status/evidence, он делает отдельный owned GET. Поэтому replay после истечения preparation term и независимого закрытия research доступа возвращает тот же безопасный receipt без новых writes и без утечки старого premium view. Исторический GET применяет ровно ту же текущую redaction, не меняя revision/digests.

## 3. Versioned persistence и уникальность

Создать additive `shared_route_current` (`profile_id` PK/FK, revision, schema version, reference-only snapshot JSON/JSONB, digest, updated_at) и `shared_route_history` (unique `(profile_id, revision)`, unique `(profile_id, client_write_uuid)`, accepted immutable receipt JSON/JSONB, canonical request digest, accepted_at, origin). Оба FK на applicant case с ORM delete-orphan для SQLite и PG. Одна Alembic head, no backfill. Пустой старый case даёт `null`/revision 0, а не автоматический converted plan. И current update, и history insert — **одна транзакция**; не может существовать current revision без matching accepted history.

Canonical request digest связывает UUID с полным typed write intent: expected revision, ordered IDs, personal choices, dates, timezone, budget/days, imported refs (если есть), preview fingerprint, G1 source fingerprint и captured legacy technical revision. Сериализация канонична и версионирована, без свободного JSON/float/порядка ключей. Server recomputes schedule/content identity; клиент не присылает авторитетные G1 claims или готовый accepted calendar. `client_write_uuid` уникален внутри profile, не глобальная authority.

## 4. Preview/save CAS и parallel replay (D2)

Предложенные endpoints остаются отдельными от legacy и G1: owned GET `.../preparation/shared-route`, POST `.../shared-route/preview` (несохранённый draft), PUT `.../shared-route` (explicit save), owned GET `.../shared-route/revisions/{revision}`. GET и history GET не требуют активного preparation term. Preview/new save требуют started term (`ACTIVE` либо `EXHAUSTED` внутри дат); не расходуют research quota. Preview показывает unsaved состояние и exact available/unallocated work. PUT требует user confirmation, `expected_revision` (0 при создании), UUID, exact preview identity, G1 selection/source digest, legacy technical revision и structural fingerprint, versioned content refs. Owner first; invalid/foreign selection 404/422 по текущему G1 контракту, source/preview/revision disagreement 409 без partial accepted plan.

Алгоритм PUT в одной транзакции:

1. `owned_profile` до любого history/result lookup. Найти `(profile_id, client_write_uuid)` **до** access и revision gate. Если запись есть: сравнить canonical request digest; равный — вернуть сохранённый immutable own receipt без записи (включая после expiry), другой — 409.
2. Для ещё не принятой команды проверить preparation access, строгую полную G1 selection в исходном порядке, текущий research display entitlement **до любого materialized evidence load**, exact own attempt refs, даты и один budget, preview/content/source fingerprints, captured legacy technical revision. Locked G1 selection может сохранять только личный practice choice с `applicability=unknown` и минимальными ID/reference digests; никакого premium requirement/имени/цели из локальной карточки. Если пользовательский choice не подтверждён или больше не доступен — 409/422 с безопасной причиной, draft остаётся у клиента.
3. Повторно считать source manifest/decisions в доступной транзакционной границе, построить **reference-only** receipt, выполнить create unique или `UPDATE ... WHERE profile_id AND revision=expected_revision`, затем вставить matching history с UUID/digest и commit. На любом сбое history insert откатить также current update. Два разных UUID с одним expected revision дают один ACK и один 409.
4. Если create uniqueness, CAS update или history uniqueness проиграны, **rollback всей проигравшей транзакции**, затем заново прочитать own `(profile_id, client_write_uuid)` в новой read transaction. С тем же digest вернуть точный принятый receipt; с иным digest — 409 UUID conflict; без строки — обычный revision 409. Так закрыта гонка, где обе доставки сначала не видели UUID. Новый retry не создаёт вторую историю.

Здесь **нет** обещания одного атомарного source writer: действующие result/claim/supersession writers не обязаны брать общий profile lock. Pre-commit recheck уменьшает окно, но не делает snapshot официально актуальным навсегда и не доказывает no check/write gap. Receipt фиксирует observed manifest при принятии; следующее own GET честно вычисляет `source_changed/needs_review` при следующем наблюдаемом изменении. Строгая межписательская гарантия потребует отдельного согласованного source revision/lock либо проверенной serializable стратегии на SQLite/PG и нового review.

## 5. Legacy revision, structural fingerprint и active view (D3)

Legacy `study_schedules` сохраняет одну строку и прежние GET/PUT shapes, `schedule-v1` IDs, `completed_task_ids`, nullable v2 `learning_path`, UUID attempts и shared CAS v1/v2. G2 таблицы их не переписывают. На preview записываются **два** legacy сигнала:

- `legacy_technical_revision`: текущий row revision нужен только для preview→PUT optimistic freshness. Любой interleaving legacy PUT/v2 sidecar PUT, включая tick-only, заставляет ещё не принятый G2 PUT ответить 409 и предложить новый preview. Это предотвращает принятие draft на не том read view.
- `legacy_structural_fingerprint`: нормализованные `ScheduleSettings` без `completed_task_ids` и с отсортированными `study_days` (семантика текущего `settings_fingerprint`). После принятия G2 **только реальное изменение этого fingerprint** может дать `legacy_structure_changed/needs_review`. Tick-only revision increment не меняет G2 history/tasks и не означает новое освоение. Технический revision сам по себе не source-stale.

Если пользователь явно импортировал v2 exact refs/owned reviews, отдельный `imported_learning_refs_fingerprint` связывает catalogue version, exact lesson/content versions и own attempt UUIDs. Его изменение даёт `imported_refs_changed`/review, независимо от legacy settings fingerprint; простой v2 save, который меняет лишь shared row revision без imported refs, не меняет G2 structural state. В первом increment можно **не импортировать** v2 sidecar, а выбрать current exact registry и own attempts явно, сохранив v2 как историю.

Сохранённый G2 — явный opt-in active shared route для основного planning/Today представления. Его **один** общий weekly/day budget заменяет legacy workload в этом представлении; v1/v2 остаются открываемыми историческими календарями и продолжают возвращать старые shape/ticks. Изменение v1 позже не запускает второй Today budget и не перестраивает accepted G2. При G2 `needs_review` Today показывает причину/сохранённые safe actions и не переключается молча обратно на legacy. Возврат на legacy как active — отдельное явное пользовательское действие и versioned event, не fallback при ошибке.

## 6. Один allocator и независимые task states

Чистый allocator принимает только личные confirmed exam choices, pinned existing exact-version catalogue/own review refs, user-entered dates/buffers/timezone, study days и **один** shared weekly budget. Сумма минут по всем exam streams за локальную ISO week ≤ shared capacity; каждый день ≤ существующего `MAX_DAILY_MINUTES=180`. Local dates, DST и deadline boundary считаются в выбранной IANA timezone. Дедупликация учебных задач — по exact compatible content ref/semantic action identity, а не похожему имени requirement или общей source page. Один урок с несколькими goal references расходует минуты один раз и не доказывает покрытие programme requirements. Missing edition/content/attempt/capacity/deadline видны как unallocated reason. Никакого автоматического certificate deadline из admission deadline; booking/results/delivery buffers — confirmed inputs.

`planned`, `self_reported_done`, `attempt_submitted`, `correctness`, `mastery=not_assessed` — разные поля/события. G2 self-report, если вводится, получает own action ID, UUID, CAS и immutable history. V1 self-ticks не копируются в G2 как факт обучения. Own attempt UUID + exact lesson/version открывает только собственный review; expired preparation сохраняет историю, но запрещает новую попытку/новый план. Retired content version не заменяется другой. Official scores, saved requirement status и research quota не меняются от действий G2.

## 7. Безопасный status probe сохранённого плана (D4)

Новый preview/save использует **строгую полную** ordered G1 selection: rejected, undecided, missing/foreign или duplicate ID блокирует весь новый draft/save. Сохранённый own GET имеет другую задачу и **не вызывает напрямую strict whole-selection G1 route** для всех старых IDs:

1. Проверить owner профиля до чтения current/history. Взять immutable ordered IDs из own reference-only receipt.
2. Одним bounded query получить только currently **owned through this profile** result metadata (ID, run, decision) для этих IDs. Отсутствующий или переставший принадлежать case ID получает одинаковый `result_unavailable` без раскрытия, существует ли он в чужой организации. `rejected`/`undecided` получает `decision_changed`. Порядок и старые action IDs остаются в receipt.
3. Проверить текущий case research entitlement **до** premium result/claim loads. Locked цель даёт фиксированный `research_locked` без имени, scope, run diagnostics, proof и digest нового source. Только сейчас owned+eligible+authorized цель может быть read-only перепроецирована как отдельный G1 slice и сравнена с сохранённым **per-goal** manifest digest. Per-slice read failure/malformed/stale даёт `evidence_unknown`/`source_changed`, не очищает историю и не повышает applicability. Цели не «помогают» друг другу стать current.
4. Составить `current_status` по каждой сохранённой цели и aggregate `needs_review`/reason. Сохранённый plan/reference receipt возвращается даже если A стал rejected, B отсутствует или нынешний G1 evidence временно недоступен. Отсутствие source read — unknown, не отсутствие требования. GET не пишет и не реконструирует план. History GET использует тот же probe/redaction либо возвращает explicit status-not-evaluated, но никогда не исторический premium ACK.

Current status probe не является existence oracle: foreign profile GET получает generic 404 до snapshot; внутри own saved selection missing и foreign result не различаются. Результат, ставший ineligible, не запрашивает premium G1 payload. Новый save не может тихо вычеркнуть такой ID: пользователь явно пересматривает ordered selection и делает новый preview с новым UUID/revision. Source supersession не меняет старый receipt.

## 8. Где уже можно работать и что остаётся неизвестным

После отдельного принятия root можно проектировать typed reference-only DTO, pure shared allocator поверх уже опубликованного exact-version content, additive tables + migration без backfill, owner GET/status probe, preview→save UUID/CAS, own export/delete и frontend opt-in с A→B→A fences. Для каждого source increment нужны отдельные hashes/gates; этот документ не разрешает начать source proposal автоматически. Дизайн сохраняет RU/EN/KK, keyboard/focus, 320/768/1024/1440, old tests и честные unavailable states.

Методически неизвестны: exact AND/OR/waiver operators, accepted exam edition/variant/retake/validity, applicable numeric minima по purpose/scope, официальные сроки и teacher-reviewed course/diagnostic quality. Поэтому current G2 scope — личный сохраняемый маршрут и общая capacity, а не merged admissions verdict, full course, official exam score или publication readiness. Строгая межписательская source serializability остаётся отдельным backend design gate.

**Review matrix для будущей реализации, не результаты:** (a) save → preparation expiry → независимое research lock → same UUID replay/history/export: receipt/digest unchanged, current evidence redacted; (b) parallel same UUID/same digest, same UUID/different digest, different UUID/same revision, history-insert rollback; (c) tick-only legacy revision, structural legacy edit, imported-ref-only edit; (d) saved `[A,B]` → A rejected, B removed/foreign/malformed → owned GET retains plan and per-goal review, new strict save refuses; (e) two exams one budget, exact content/attempt refs, DST, unallocated work, export/delete and sibling isolation.
