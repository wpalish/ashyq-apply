## Recovery and caller obligations

1. The owning tree supplies exact verified owner scope, server case ID, monotonically changing case epoch and a live callback. Binding is checked around every storage read/write, async digest and ACK. Scope undefined requires **natively explicit demo**, never an unbound anonymous browser.
2. Every fresh case family has a random UUID **generation/instance token**, while case epoch, draft generation and entry revision are bounded integers. A cleared/reopened A→B→A family cannot reuse old numeric0 authority. Exact case-key encoding escapes the delimiter, so `case-a` cannot scan/delete `case-a.more`.
3. `journalAdmissionsAction` must succeed before caller dispatch. Unknown response retains original UUID/body; `admissionsActionRetryBody` returns only that original intent for an explicit retry. Conflict requires explicit review/new UUID for changed body/CAS; no automatic dispatch or retry on hydration/navigation.
4. ACK caller inputs are copied before awaits. A closed matching own immutable receipt, request/receipt digest, UUID and semantics are required. Only that UUID becomes acknowledged; sibling/newer pending entries and drafts survive. The helper never applies the ACK delta to mutable server current; caller must reload current through the native API.
5. Server typed UTC canonical hashes use `+00:00`, six fractional digits when microseconds are nonzero and no fraction when zero. JSON may use `Z`/short fraction. Only known typed UTC/UUID fields are normalized for **comparison**; original submitted body is retained, and applicant local date/time/notes remain unchanged. Tests include an actual-shaped select-plan command/ACK fixture signed over explicit server-canonical typed values, without importing/running application code.
6. Index is advisory. Every entry key is derived from verified binding + canonical UUID, never read from an arbitrary index key. Reads compare the bounded physical family to the index. Invalid/foreign/oversized/lost/mismatched bytes cause refusal and are retained. Explicit reviewed `reconcileAdmissionsActionsIndex` can recover valid own entries after index loss/interleaving; it refuses invalid/foreign index or entry bytes. There is no localStorage atomic CAS or cross-tab transaction claim.
7. Only call `acknowledgeAdmissionsCaseDeletion` after the native DELETE for the captured own case **successfully resolves**, before the store changes its case epoch. An unresolved/failed DELETE gives no cleanup authority. A separate immutable tombstone survives a late alive-fence initializer or late pending write. Cleanup is exact case family only, best effort; failure/interleaving/malformed extra keys return `residual_unknown`. This is not certified erasure. Existing native acknowledged logout/auth-owner reset clears the scoped applicant family unchanged.
8. Legacy browser marks are literal-true explicit candidates with unknown historical time/source. Key/snapshot digests are references; no automatic name, result ownership or version matching. Applicant must choose exact own task mappings, at most50, and preview source-bound mappings through the authorized API. ACK never removes/rewrites raw `ashyq.docsDone`, false-to-true edits or unrelated keys. Test covers exact raw retention.
