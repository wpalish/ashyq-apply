## F1 — Today controls looked up a schedule by the profile primary key

**First snapshot: test blocker. Source closure: confirmed in separate repair1.**

Original `test_today.py` lines **97, 184, 258, 377** use `session.get(StudyScheduleRow, lab["case"])`. `Session.get` uses the model primary key. Native `StudyScheduleRow` inherits the independent generated `TimestampedBase.id`; the native schedule writer assigns `profile_id` without assigning `id`. The reused lab does not make those IDs equal.

Consequences: `make_v2` dereferences a missing row; malformed-sidecar, selected-plan deletion and native-plan interleaving controls similarly operate on `None` instead of the own schedule. They cannot establish the intended coverage in that first snapshot. This is a fixture/control mistake, not a reason to change the native model or writer.

Repair1 changes exactly those four expressions to `session.query(StudyScheduleRow).filter_by(profile_id=lab["case"]).one()`. The own case predicate is explicit; missing or duplicate rows still fail. Full diff inspection shows no changed imports, assertions, parameters, callback branches, test scenarios or native source. The original defective packet remains immutable and unqualified for execution.
