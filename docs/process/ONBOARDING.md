# Передача разработки алгоритма (2026-09-28)

Ты продолжаешь разработку алгоритма в репозитории `wpalish/ashyq-apply`. Это сервис, который по профилю
абитуриента (сейчас из Казахстана) собирает шорт-лист университетов и стипендий. Каждое значение в нём
подкреплено цитатой с официальной страницы и датой.

## 1. Прочитай сначала, в таком порядке
- `AGENTS.md` — общие правила репозитория, обязательны.
- `CLAUDE.md` — дополнения для Claude.
- `docs/process/HANDOFF.md` целиком. Особенно разделы §2 (текущая задача), §5 (следующий шаг), §8 (изменения
  контракта), §9 (грабли) и записи от 2026-09-27/28 в конце.
- `backend/evaluation/research/expert/data/hypotheses.json` — реестр гипотез ER-01…ER-07 со статусами и
  доказательствами.
- `backend/evaluation/research/README.md` — как устроена оценка.

## 2. Что уже есть
- **Пайплайн** `backend/app/pipeline/runner.py`, по этапам:
  - discovery: поиск университетов и страниц программ (`app/adapters/discovery`, `app/adapters/search`);
  - verify: требования и стоимость (`app/adapters/requirements`, `app/adapters/cost`);
  - funding: стипендии (`app/adapters/scholarship/web_scholarships.py`);

- **Извлечение фактов** — правилами, без LLM: `app/adapters/extraction.py`. Классификация страниц —

- **Эталон**: `backend/evaluation/research/data/ground_truth.reviewed.json`, 10 университетов и 62 проверенных
  факта. Привязки стипендий и документов к ключам фактов — `identity_bindings.reviewed.json`.
- **Метрики** (последний живой прогон, 36400210111): полнота 9/62, точность 10/11.
- **Оракул** `evaluation/research/oracle.py` открывает страницу-источник каждого эталонного факта напрямую и
  говорит, извлекается ли факт. Он разделяет две проблемы: «страницу не нашли» и «нашли, но не прочитали». С 28.09
  он измеряет и стипендии. Итог: 12 извлечено, 26 не найдено на скачанной странице, 18 не скачано,
  15 не измеряется.
- **Решения владельца, уже реализованные:**
  - Дедлайн раньше, чем за год и месяц до начала учёбы, считается дедлайном прошлого цикла. Он хранится в
    `previous_cycle_deadline` и помечается как «previous cycle», а не «passed».
  - ER-02: кампус — отдельный параметр программы. Данные о кампусах лежат в реестре
    `app/adapters/discovery/institution_registry.json` в поле `campuses`, пока только для Торонто. Если кампус в
    запросе не указан, факты со страниц кампуса скрываются и задаётся вопрос. Правило пока не покрывает этап
    стипендий и не измерено вживую.
- **Проверенные и отвергнутые гипотезы:**
  - ER-04, ER-05, ER-07 — отвергнуты, ER-06 — нейтральна.
  - Их переключатели выключены в `live_discovery.py`.
  - Отрицательные результаты храним, не удаляем.

## 3. Как работать
- **Проверки перед каждым коммитом** (из `backend/`):
  ```
  .venv/bin/ruff format --check app tests evaluation
  .venv/bin/ruff check app tests evaluation
  .venv/bin/mypy app tests evaluation
  .venv/bin/pytest -q --cov=app --cov-fail-under=92 -p no:cacheprovider
  ```
  Полный набор тестов идёт около 15 минут. Фронтенд проверяется в `frontend/` командами `npm run typecheck`,
  `npm run lint`, `npm test`. E2E-тесты в `frontend/e2e` проверяют пользовательский путь, и изменения в выдаче
  могут их ломать.
- **Живое чтение сайтов — только через GitHub Actions**, workflow `.github/workflows/benchmark-capture.yml`
  (ручной запуск):
  - `mode=benchmark` — полный прогон, метрики и оракул;
  - `expert_paired` — парное сравнение с переключателем: `base_args` задаёт общие параметры, `extra_args` —
    отличие.
  - Логи скачиваются по ссылке из API задания (job logs).
  - Все тесты работают офлайн.
- **Эталонный хэш демо** `GOLDEN_DEMO_SHA256` лежит в `tests/test_freshness_regressions.py`. Выдача демо должна
  совпадать байт в байт. Менять хэш можно, только если изменение добавочное, или это решение владельца. В обоих
  случаях рядом с хэшем пишется доказательство.
- **После изменений в `runner.py` или `scoring.py`** запусти `seed_demo.py` и сверь порядок с брифом §5.7.
- **Гипотезы:**
  - проверяй по одной, на парных прогонах с одинаковым бюджетом, включая отложенные университеты;
  - записывай результат в `hypotheses.json`: допустимые статусы — observed, candidate, tested, rejected,
    promoted; набор полей фиксирован, его проверяет тест;
  - записывай результат в HANDOFF, с хэшем коммита.

## 4. Запреты
- Никогда не коммить `backend/data/*`, `.env*`, API-ключи и данные абитуриентов. Перед коммитом проверь изменения
  поиском по ключам.
- Не обходить robots.txt, не подделывать User-Agent, не использовать прокси.
- Не править эталонные метки корпуса.
- Не выдавать вероятность поступления: только соответствие опубликованным критериям.
- Коммиты — в свою ветку, в main — только через PR. Никакого force-push в чужие ветки.
